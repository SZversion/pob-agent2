# PoB Agent

> 상태: 전체 질문·계산 흐름은 미구현입니다. Agent의 상태 파일 수신과 UI는 일부 구현됐고, PoB 송신 코드는 Git에서 추적하지 않는 개발용 복사본에만 있습니다. 감시자 코드는 실제 PoB PID 발견을 진단 환경에서 확인했으며 Agent 자동 실행, 설치·설정·배포 연결은 남아 있습니다. 설치본 적용은 미구현입니다.

PoB Agent는 Path of Building(PoB)과 분리된 서드파티 프로그램으로 계획하고 있습니다. 별도 감시자는 기본적으로 Windows 로그인 때 실행되며, PoB를 감지하면 Agent 앱을 시작하고 PID를 전달합니다. PoB에는 최소 연결 코드를 적용해 활성 빌드가 바뀔 때 저장 파일 경로만 Agent에 알립니다. Agent는 연결된 PoB의 저장 빌드를 기본 맥락으로 삼고, 다른 저장 빌드는 사용자의 자연어 요청에 따라 찾아 분석합니다. 사용자가 별도로 준비한 PoB 소스와 LuaJIT 실행 파일은 계산을 위해 별도 프로세스에서 실행합니다.

연결은 [PoB 측 상태 송신](docs/features/pob-side.md), [PoB 프로세스 감시자](docs/features/pob-watcher.md), [Agent 측 브리지](docs/features/pob-bridge.md)의 세 단계로 나눕니다. 설치본에 송신 코드를 적용하는 절차는 [브리지 설치](docs/features/pob-bridge-install.md)에 따로 정의합니다.

연동은 빌드 파일의 경로만 전달합니다. PoB의 메모리 상태, 계산값, 빌드 내용 또는 저장하지 않은 변경 사항은 가져오지 않습니다. PoB 화면을 조작하거나 빌드를 수정하지 않습니다.

## 첫 개발 목표

대표 사용자 질문 하나를 처음부터 끝까지 검증합니다. 질문의 한국어·영어 명칭을 해석하고, 필요한 도구에 정확한 인자를 전달하며, 빌드 파일의 재계산 결과와 조회한 근거에 맞는 한국어 답변을 반환해야 합니다. 도구 오류나 근거 부족이 있으면 확인하지 못한 내용을 단정하지 않습니다.

“뇌동의 연쇄번개”는 한국어와 영어 스킬 명칭을 연결해야 하는 상황의 예시입니다. 특정 스킬을 필수 통과 테스트로 고정하지 않습니다.

## 원칙과 현재 범위

- 빌드 수치의 근거는 입력 빌드 파일과 사용한 PoB 계산 엔진·데이터 버전으로 재계산한 결과입니다. 모델이 수치를 자체 계산하거나 추정해 확정값으로 제시하지 않습니다.
- 빌드 파일은 로컬에서 처리하고, 외부 모델을 사용할 때에는 답변에 필요한 최소 정보만 전달합니다. 자격 증명은 빌드 파일, 로그, trace에 포함하지 않습니다.
- 첫 흐름을 검증하기 전에는 도구나 기능의 수를 늘리지 않습니다.
- 감시자의 시작 방식 설정, PoB 프로세스 선택, 활성 저장 빌드 경로 전달과 빌드 변경 시 자동 갱신은 첫 개발 목표에 포함됩니다. PoB 창 조작, 빌드 내용·메모리 읽기, 빌드 편집·저장, 추천·최적화는 포함되지 않습니다.

PoB 업데이트 후 연결 코드를 다시 적용해야 합니다. 사용자가 준비할 PoB 소스 및 LuaJIT의 경로 설정, 버전 호환성과 라이선스 고지는 아직 결정되지 않았습니다. 구현 전에 이 항목들을 명세하고 검증해야 합니다.
