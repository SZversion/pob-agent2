# 서비스 연동 및 사용자 흐름

> 상태: 제품 동작 합의. 실제 PoB 연동, 자동 실행, 오버레이는 구현 전입니다.

## 제품 형태

PoB Agent는 PoB와 분리된 데스크톱 프로그램입니다. 사용자는 PoB를 실행한 상태에서 화면 위의 작은 오버레이 버튼을 눌러 채팅창을 열고 에이전트와 대화합니다. 첫 버전의 목적은 PoE1 빌드의 딜 메커니즘을 설명하는 것입니다.

## 시작과 PoB 감지

1. 사용자가 PoB Agent를 설치하고 서비스 창에서 **PoB 연동**을 누릅니다.
2. Agent는 설치된 PoB에 최소 연결 코드를 적용해 두 동작을 활성화합니다.
   - PoB에서 활성 빌드가 바뀔 때마다 저장 파일의 식별 경로만 Agent에 전달
   - PoB가 실행될 때 Agent도 함께 시작
3. 이후 PoB가 실행되면 연결 코드가 Agent를 시작합니다. Agent는 PoB 실행을 기다리며 상시 대기하지 않습니다.
4. Agent가 실행된 뒤 Windows에서 현재 활성화된 창이 PoB인지 감지해 오버레이 표시 여부를 결정합니다.
5. 오버레이 표시 설정은 다음 두 가지를 제공합니다.
   - **PoB가 활성화됐을 때만 표시** — 기본값
   - **항상 표시**
6. PoB가 활성 창일 때는 모니터 오른쪽 아래에 작은 오버레이 버튼을 표시하고, 설정이 항상 표시이면 Agent가 실행 중인 동안 PoB가 비활성 상태여도 버튼을 표시합니다.
7. 사용자가 버튼을 누르면 별도의 채팅창을 열어 에이전트와 대화합니다.

오버레이는 PoB 화면 위에 표시되는 Agent의 별도 UI입니다. PoB UI에 버튼을 삽입하거나 PoB 창의 입력을 자동 조작하는 방식으로 정의하지 않습니다.

## Agent 단일 실행 및 수명

- Agent는 사용자 세션에서 하나만 실행합니다. PoB 연동 코드가 Agent를 시작하면, Agent는 UI나 MCP 서버를 준비하기 전에 이름 있는 Windows mutex를 확보합니다.
- mutex 확보에 성공한 첫 PoB 인스턴스만 Agent와 연결됩니다. Agent는 그 PoB 프로세스 ID와 선택된 빌드 파일 경로를 기준으로 동작합니다.
- mutex가 이미 존재하면 새 Agent 실행은 거부됩니다. 두 번째 PoB에 연결된 시작 요청은 사용자에게 이미 다른 PoB와 연결되어 있음을 알리고, 새 UI나 MCP 서버를 열지 않습니다. 기존 Agent의 연결은 유지합니다.
- Agent는 연결된 첫 PoB의 종료를 Windows 프로세스 핸들로 기다립니다. 해당 PoB가 종료되면 Agent가 정리 후 종료합니다.
- 빌드 경로 전달은 연결된 PoB 인스턴스에서만 받습니다. 활성 빌드 변경 때 전달되는 빌드 데이터는 저장 파일 경로뿐입니다.

다른 PoB가 계속 실행 중인 상태에서 연결된 첫 PoB가 종료된 경우, 남은 PoB로 자동 전환할지 또는 사용자가 다시 연동해야 하는지는 미결정입니다.

## 활성 빌드 전달 및 재계산

1. PoB에서 활성 빌드가 바뀔 때마다 연결 코드는 해당 빌드의 저장 파일을 식별하는 경로만 Agent에 전달합니다.
2. Agent는 전달받은 경로의 저장된 빌드 파일을 로컬에서 읽습니다.
3. Agent는 포함할 PoB 계산 엔진을 LuaJIT으로 실행해 빌드 수치를 재계산합니다.
4. 모델은 사용자의 질문에 맞는 도구를 선택하고, 재계산 결과 및 검색 근거를 한국어로 설명합니다.

저장되지 않은 PoB 변경 사항은 반영하지 않습니다. 연결은 파일 경로만 전달하며 PoB 메모리에서 빌드 데이터나 계산값을 읽지 않습니다. Agent는 PoB UI를 조작하지 않고 빌드를 수정하거나 저장하지 않습니다.

## 답변 근거

- 수치 주장은 입력 빌드 파일과 명시된 PoB 엔진·데이터 버전으로 재계산한 결과를 사용합니다.
- 스킬 설명이나 재계산 결과만으로 알 수 없는 게임 메커니즘은 인터넷 검색으로 보완하고, 출처를 답변에 제시합니다.
- 모델은 계산 결과를 설명할 뿐 수치를 직접 계산하거나 근거 없이 단정하지 않습니다.
- 빌드 파일은 로컬에서 처리합니다. 외부 모델과 로그·trace에는 필요한 최소 정보만 전달하며 자격 증명을 기록하지 않습니다.

## 실패 시 동작

- PoB가 감지되지 않거나 연동되지 않은 경우 사용자가 상태를 알 수 있게 표시합니다.
- 빌드 경로가 유효하지 않거나 파일을 읽을 수 없으면 다른 빌드의 결과를 대신 사용하지 않고 실패 이유를 알립니다.
- 엔진 계산 실패, 인터넷 검색 실패 또는 근거 부족이 있으면 확인되지 않은 내용을 확정하지 않습니다.
- PoB 업데이트 후 연결 코드가 호환되지 않을 수 있으며, 재연동이 필요할 수 있음을 알립니다.

## 미결정 구현 사항

- 기존 연결 PoB가 종료될 때 다른 실행 중인 PoB로 자동 전환할지 여부
- PoB 활성 창을 식별하는 구체적인 방법과 지원할 PoB 버전 범위
- 연결 코드의 설치, 버전 확인, 업데이트 후 재적용 및 제거 방식
- 활성 빌드 파일 경로를 알리는 코드와 Agent 사이의 IPC 방식
- 오버레이의 Windows 창 동작, 디스플레이별 위치, 접근성 및 설정 저장 방식
- 포함할 PoB 계산 엔진의 버전·배포·라이선스 처리
- Colab 모델 연결·인증 및 웹 검색 공급자

이 문서는 합의한 사용자 동작과 아직 설계가 필요한 구현 방식을 구분합니다. 구현되기 전의 동작을 완료된 기능으로 표시하지 않습니다.
