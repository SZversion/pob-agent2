# MCP 실행 및 계산기 호출 방식

> 상태: 설계 합의. 구현 및 통합 검증 전입니다.

## 목적

MCP는 에이전트가 사용할 도구를 표준 방식으로 발견하고 호출하게 하는 통신 규약입니다. MCP 서버는 별도 백엔드 서비스로 배포하지 않고, 데스크톱 앱이 로컬에서 실행하는 Python 프로세스로 구성합니다.

## 합의한 실행 흐름

```text
데스크톱 앱의 MCP 클라이언트
  ↔ stdio
uv가 실행한 Python MCP 서버
  → MCP 도구 핸들러
  → 별도 LuaJIT 자식 프로세스
  ↔ stdio JSON Lines
  → 사용자가 별도로 준비한 PoB Lua 계산 코드
```

- 앱은 `uv`를 통해 Python MCP 서버를 실행하고 `stdio`의 표준 입력·출력으로 요청과 응답을 주고받습니다.
- Python MCP 서버는 도구 이름, 입력 스키마, 결과 및 오류 반환을 MCP 규약에 맞게 처리합니다.
- Python MCP 서버는 시작할 때 LuaJIT 자식 프로세스를 실행하고, LuaJIT 준비가 완료되어야 MCP 서버 시작을 완료합니다. LuaJIT 시작 제한은 10초입니다.
- 각 도구 핸들러는 받은 인자를 검증하고 해당 Python 기능을 호출합니다. 계산이 필요한 기능은 PoB UI 프로세스와 분리된 LuaJIT 자식 프로세스에 요청합니다.
- Python과 LuaJIT은 표준 입력·출력으로 한 줄마다 JSON 요청과 응답을 주고받습니다. Agent에 포함하는 프로젝트 소유 Lua 어댑터가 JSON Lines 요청을 처리하고 PoB headless API를 호출합니다. 진단 로그는 stderr로 보내며 프로토콜 출력과 섞지 않습니다.
- LuaJIT 자식 프로세스는 프로젝트 소유 Lua 어댑터를 통해 사용자가 별도로 준비한 PoB 소스의 Lua 계산 코드를 headless 방식으로 실행합니다. 설치된 PoB GUI 프로세스의 메모리나 내장 런타임에 연결하지 않습니다. Agent 패키지에는 PoB 계산 소스와 LuaJIT 실행 파일을 포함하지 않습니다.
- MCP 서버는 웹 서버 포트를 열거나 별도의 상시 백엔드에 연결하지 않는 로컬 `stdio` 방식으로 설계합니다.
- MCP 앱 준비 절차는 MCP와 모델 연결에 이미 합의된 10초 제한, 0.5초 간격, 총 3회 시도를 적용합니다. LuaJIT이 10초 안에 시작하지 못하면 MCP 시작을 실패 처리합니다.

## 책임 경계

| 구성요소 | 책임 |
| --- | --- |
| 데스크톱 앱 | MCP 서버 실행·종료와 연결 관리, 사용자 인터페이스 및 모델 연결 |
| Python MCP 서버 | 도구 목록과 입력 규격 제공, MCP 요청을 핸들러에 전달하고 결과 반환 |
| 도구 핸들러 | 인자 검증, 도메인 기능 호출, 오류를 식별 가능한 형태로 반환 |
| LuaJIT 계산 프로세스 | PoB Lua 계산 코드 실행 및 계산 결과 반환 |
| PoB 계산 엔진 | 빌드 입력에 대한 게임 수치 계산 |

## 데이터와 결과 원칙

- 빌드 파일은 로컬에서 읽고 계산합니다.
- 계산 수치는 입력 빌드 파일과 사용한 PoB 엔진·데이터 버전을 기록 가능한 재계산 결과에 근거합니다.
- 모델은 도구를 선택하고 결과를 설명합니다. 모델이 계산 수치를 만들어내거나 확인되지 않은 수치를 확정하지 않습니다.
- 외부 모델, 로그 및 trace에는 요청 처리에 필요한 최소 정보만 전달하며 자격 증명은 기록하지 않습니다.
- 오류, 시간 초과, 지원하지 않는 입력, 계산 결과 부족을 성공 응답처럼 숨기지 않습니다.
- 요청당 시간 제한은 10초이며 최초 시도를 포함해 최대 3회 시도합니다. LuaJIT 프로세스 종료, 표준 입출력 통신 실패, 시간 초과만 재시도합니다. 재시도 전 기존 LuaJIT을 종료하고 새 프로세스를 즉시 시작하며 실패한 요청을 재전송합니다.
- 입력 검증 오류와 PoB 계산 오류는 재시도하지 않고 각각 구분해 도구 오류로 반환합니다. 모델 연결 또는 모델 응답 실패는 LuaJIT 프로세스를 재시작하지 않는 별도 오류입니다.
- 세 번 모두 프로세스·통신 실패가 나면 해당 요청을 실패로 반환합니다. Python MCP 서버는 계속 실행하며 다음 계산 요청에서 새 LuaJIT 프로세스로 복구를 시도합니다.

## 아직 정하지 않은 사항

- 데스크톱 앱과 모델 간의 구체적인 호출 프로토콜 및 Colab 연결·인증 방식
- MCP SDK와 서버 구현 라이브러리의 선택
- `uv`와 Python 런타임을 개발·최종 배포에서 각각 어떻게 제공할지
- 표준 입출력 JSON Lines 메시지의 세부 스키마와 오류 코드 이름
- 사용자가 준비한 LuaJIT 실행 파일과 PoB 소스 경로의 설정·탐색 방식, 버전 호환성과 라이선스 고지

위 항목은 구현 전에 별도 명세와 검증이 필요합니다.
