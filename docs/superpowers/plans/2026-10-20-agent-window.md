# Agent Window Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Create a runnable Electron desktop app that displays the approved PoB Agent chat window design.

**Architecture:** Electron main owns one resizable window; React renders the chat and blank settings view through Vite. Keep renderer Node access disabled and leave PoB, MCP, and model integrations unimplemented.

**Tech Stack:** Electron, electron-vite, React, TypeScript, Vite, npm.

**Spec:** `docs/superpowers/specs/2026-10-20-agent-window-design.md` and `docs/features/agent-window.md`

## Global Constraints

- The app uses Electron, React, TypeScript, and Vite.
- The main window starts at 960×720, is resizable, and does not persist its size.
- Chat and UI state remain in memory only.
- The renderer gets no Node/Electron access; use a narrow preload boundary.
- Preview messages and connection/build labels are fixture content, not live PoB or calculation data.
- No PoB, MCP, model, packaging, or installer integration is part of this slice.
- Do not add automated tests; validate with typecheck, build, and a manual desktop launch because the user requested implementation, not tests.

## Review Focus

- Window resize and small viewport: preserve the composer and keep the message area scrollable; manually inspect at 960×720 and a narrower size.
- Settings navigation: opening and returning to chat must work without persistence; manually click both directions.
- Preview fixture: sample messages and connected/build labels must remain explicit static preview data and must not be sent as a calculation result.
- Disabled integrations: the composer and build selector must not report successful actions before a bridge exists.
- Renderer isolation: verify `nodeIntegration: false`, `contextIsolation: true`, and `sandbox: true` in the Electron window configuration.
