# 기능 정의

> 상태: 제품 범위 합의. 기능은 아직 구현되지 않았습니다.

## 제품 목표

PoB Agent는 Path of Building (PoB)과 분리된 Windows 데스크톱 서드파티 프로그램입니다. PoE1 빌드 파일을 로컬에서 재계산하고, 빌드의 딜 메커니즘을 한국어로 설명합니다.

## 대상 사용자와 해결할 문제

PoB로 PoE1 빌드를 관리하며, 빌드의 피해 수치가 어떤 구성과 상호작용에서 나오는지 이해하려는 사용자입니다. 사용자가 현재 PoB에서 선택한 저장 빌드를 별도로 찾아 Agent에 지정하는 부담을 줄이고, 계산 근거를 바탕으로 설명을 제공합니다.

## 사용자 흐름

1. 사용자가 Agent에서 PoB 연동을 시작합니다.
2. Agent는 설치된 PoB에 필요한 최소 연결 코드를 적용합니다.
3. 연결된 PoB가 실행될 때 Agent도 시작됩니다.
4. Agent는 가장 먼저 연결을 성립시킨 PoB 인스턴스 하나에 연결됩니다. 한 번에 실행되는 Agent도 하나입니다.
5. PoB에서 활성 빌드가 바뀌면 연동 코드가 저장된 빌드 파일의 식별 경로만 Agent에 전달합니다.
6. Agent는 그 경로의 저장 파일을 로컬에서 읽고, 포함할 PoB 계산 엔진을 LuaJIT으로 실행해 필요한 수치를 재계산합니다.
7. 사용자는 PoB가 활성화된 동안 기본 표시되는 오버레이 버튼을 누르고 채팅창에서 빌드에 관해 질문합니다. 설정을 바꾸면 오버레이를 항상 표시할 수 있습니다.
8. Agent는 계산 결과와 검색 근거를 바탕으로 한국어 답변을 제공합니다.

## 첫 버전 In Scope

- PoE1 지원. PoE2는 지원 계획이 없습니다.
- PoB와 분리된 Agent 데스크톱 앱.
- Agent 설정 화면에서 시작하는 PoB 연동 및 설치된 PoB에 최소 연결 코드 적용.
- 연결된 PoB의 시작과 함께 Agent 실행.
- 사용자 세션당 Agent 단일 실행. 이미 Agent가 실행 중이면 두 번째 Agent 실행은 거부하고 사용자에게 알립니다.
- 최초로 연결된 PoB 인스턴스 하나만 사용. 다른 PoB 인스턴스 요청은 대기열에 넣지 않고, 기존 연결 종료 후에도 자동 전환하지 않습니다.
- 연결된 PoB의 프로세스 종료를 감지하고 Agent 정리 및 종료.
- PoB 활성 빌드 변경 시 저장 빌드 파일의 식별 경로만 전달하고, Agent가 해당 파일을 로컬에서 읽음.
- PoB 계산 엔진을 LuaJIT으로 실행해 빌드 수치를 재계산.
- PoB 활성 상태에서 기본 표시되는 작은 오버레이 버튼과 버튼에서 여는 채팅창.
- 오버레이 표시 설정: PoB가 활성화됐을 때만 표시(기본값), 항상 표시.
- PoB 계산 결과에 근거한 딜 메커니즘 설명.
- 수치의 빈 근거는 PoB 재계산 결과로 채움. 스킬 설명이나 계산 결과만으로 확인할 수 없는 게임 메커니즘은 인터넷 검색으로 보완하고 출처를 제시.
- 한국어 및 영어 명칭 해석 지원. “뇌동의 연쇄번개”는 명칭 해석의 예시이며 필수 통과 테스트가 아님.
- 도구 오류, 계산 실패 또는 근거 부족 때 확인되지 않은 내용을 단정하지 않고 실패/한계를 사용자에게 알림.

## 첫 버전 Out of Scope

- PoE2 지원.
- 여러 PoB 인스턴스 간 대기열, 자동 전환, 빌드 상태 동기화.
- PoB 메모리나 화면에서 빌드 내용 또는 계산값 읽기.
- PoB 창 조작, 빌드 수정 또는 저장되지 않은 변경사항 반영.
- 빌드 편집, 추천, 최적화 또는 자동 변경.
- 근거 없이 모델이 빌드 수치를 직접 산출하거나 확정하는 기능.
- 검증된 대표 흐름을 완성하기 전에 여러 도구나 부가 기능을 확장하는 일.

## 제품 불변 조건

- **계산의 권위:** 확정 수치는 입력 빌드 파일과 사용한 PoB 엔진·데이터 버전으로 재계산한 결과를 근거로 합니다.
- **모델 역할:** 모델은 질문을 해석하고 도구를 선택하며 계산·검색 결과를 설명합니다. 계산 수치를 자체 산출하거나 근거 없이 확정하지 않습니다.
- **빌드 입력 경계:** PoB 연동 코드는 활성 빌드의 저장 파일 식별 경로만 전달합니다. 파일 내용은 Agent가 로컬에서 읽습니다. 저장하지 않은 변경사항은 대상이 아닙니다.
- **프로세스 경계:** Agent는 PoB UI를 조작하거나 PoB 메모리에서 데이터를 읽지 않습니다.
- **개인정보와 자격 증명:** 빌드 파일은 로컬에서 처리합니다. 외부 모델·로그·trace로 보내는 데이터는 요청 처리에 필요한 최소 범위로 제한하고 자격 증명은 기록하지 않습니다.

## 이후 버전 후보

아래 항목은 제안 후보이며 승인된 범위가 아닙니다.

- 여러 PoB 인스턴스 사이의 연결 전환.
- PoE2 지원.
- 빌드 추천·비교·최적화.
- 추가 분석 도구와 사용자 흐름.

## 구현 전에 정할 사항

- 포함할 PoB 계산 엔진과 데이터의 범위, 버전 고정, 배포 및 라이선스 처리.
- PoB 업데이트 시 연결 코드의 호환성 확인, 재적용, 제거 및 복구 절차.
- 지원할 PoB 버전과 빌드 파일 경로를 얻는 구체적 연동 지점.
- PoB와 Agent 사이의 경로 알림 IPC 및 연결 인스턴스 식별·검증 방법.
- 오버레이의 구체적인 창 동작, 모니터별 배치, 접근성 및 설정 저장 방식.
- 외부 모델(현재 구상: Colab) 연결·인증 및 웹 검색 공급자.
- 계산 결과 직렬화와 앱·Python MCP·LuaJIT 간 요청/오류 처리 방식.
