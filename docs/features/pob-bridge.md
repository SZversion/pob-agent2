# Agent 측 PoB 브리지

> 상태: 상태 파일 수신과 연결 후보 표시·수동 선택은 앱에 일부 구현됐다. 감시자의 PID 전달, 단일 후보 자동 연결, 설치본 적용, 분석 요청 연동은 아직 구현되지 않았다.

이 문서는 Agent가 PoB의 상태 파일을 읽어 연결 대상을 정하고 활성 저장 빌드 경로를 관리하는 동작만 정의한다. PoB의 파일 송신은 [PoB 측 상태 송신](pob-side.md), Agent 실행과 후보 PID 전달은 [감시자](pob-watcher.md), 브리지가 없는 설치본의 준비는 [브리지 설치](pob-bridge-install.md), 선택 UI는 [PoB 프로세스 선택기](pob-process-selector.md)를 따른다.

## 입력과 연결 대상

- 감시자가 반복된 `--pob-pid=<PID>` 실행 인자로 전달한 전체 최초 PID 목록은 연결 후보이며 자동 선택 지시가 아니다. Agent가 이미 열려 있고 연결 대상이 없으면 Electron 단일 인스턴스 이벤트로 목록을 받는다. Agent는 최초 목록을 모두 받은 뒤 연결 가능 후보 수를 판단한다. 한 번 대상을 선택한 뒤에는 이후 후보가 현재 연결을 바꾸지 않는다.
- Agent를 수동 실행했을 때 PoB가 없으면 연결 해제 상태로 대기한다. 브리지가 설치된 PoB가 하나만 연결 가능하면 자동 연결하고, 여러 개면 감시자가 전달한 PID와 관계없이 사용자가 프로세스를 선택한다.
- 최초 연결 후에는 UI와 IPC 모두 다른 PoB로 전환하지 않는다. 선택한 PoB가 종료되면 Agent도 종료하고 다른 실행 중인 PoB로 자동 승계하지 않는다.
- 브리지가 설치되지 않아 상태 파일을 보낼 수 없는 PoB는 [브리지 설치](pob-bridge-install.md)의 연결 버튼 흐름으로 안내한다.

## 상태 파일 수신

- Agent는 `app.getPath('userData')/pob-bridge` 디렉터리를 만들고 감시한다. Windows 기본 위치는 `%APPDATA%\pob-agent\pob-bridge`이며 PoB 송신기도 같은 위치를 사용한다. 파일 형식은 [PoB 측 상태 송신](pob-side.md)에 정의한다.
- 시작 시 디렉터리를 읽고 `fs.watch` 알림이 오면 다시 읽는다. Agent는 파일 이름과 내용의 PID가 일치하는지, PID가 유효하고 감시자가 확인한 실행 중인 `Path of Building.exe`의 PID인지, `buildPath`가 문자열 또는 `null`인지 검사한다. 빌드 XML 자체는 감시하지 않는다.
- 유효한 빌드 경로는 로컬에서 읽을 수 있는 저장 XML 파일이어야 한다. 화면에 표시할 빌드명과 다른 저장 빌드 검색 폴더는 이 경로에서 얻는다. 경로가 `null`이거나 파일이 없거나 읽을 수 없으면 이전 빌드를 현재 빌드로 유지하지 않는다.
- 종료된 PID의 상태 파일을 정리하고 후보에서 제거한다. 선택된 PID가 종료됐으면 Agent를 종료한다. 선택되지 않은 PoB의 경로 변경은 현재 빌드 맥락을 바꾸지 않는다.
- `fs.watch` 알림은 누락될 수 있다. 이 경우 다음 파일 변경이나 Agent 재시작 전까지 경로 반영이 늦어질 수 있어 Windows 통합 검증이 남아 있다.

## 분석 요청에 전달할 빌드 맥락

- 선택된 PoB의 현재 활성 저장 빌드 경로가 기본 빌드 맥락이다. “이 빌드”, “우리 빌드”는 이 경로를 가리킨다. 저장되지 않은 변경 사항은 반영하지 않는다.
- 진행 중인 요청은 시작할 때 확정한 경로를 계속 사용하고, 빌드 전환은 다음 요청부터 적용한다. 경로가 바뀌어도 대화와 대기열을 지우지 않는다.
- 사용자가 다른 저장 빌드명을 명시하면 현재 경로의 상위 폴더에서 찾고 해당 요청에만 사용한다. 후보가 하나면 분석하고 여러 개면 확인을 받으며 찾지 못하면 이름을 구체화하도록 요청한다. 이 검색은 기본 맥락을 바꾸지 않는다.
- Agent는 저장 빌드 파일을 로컬에서 읽는다. PoB 메모리, 빌드 내용·계산 결과의 직접 전송, PoB UI 조작과 빌드 수정·저장은 범위에 포함하지 않는다. 계산 도구 및 모델 연결은 [MCP 문서](../MCP.md)와 [Agent 창](agent-window.md)을 따른다.

## 현재 구현과 남은 작업

- `src/main/pob-bridge.ts`는 상태 파일을 읽고 파일 이름·내용의 PID 일치, PID 생존 및 경로를 검사하며 후보 목록을 관리한다. 현재는 감시자가 확인한 PoB PID와 대조하지 않는다. `src/main/index.ts`와 preload/렌더러는 후보 표시와 수동 선택을 제공한다. 아직 빌드 XML 내용 읽기나 분석 요청 연결은 없다.
- 단일 후보 자동 연결, 감시자의 전체 최초 PID 목록을 담은 실행 인자와 단일 인스턴스 이벤트 수신, 설치 버튼 흐름은 구현되지 않았다.
- 개발용 PoB 복사본 및 패키징된 Agent를 함께 실행해 빌드 전환, PoB 종료, `fs.watch` 누락과 비ASCII 경로를 검증해야 한다.

## 완료 기준

- 감시자가 확인한 PoB PID와 일치하는 상태 파일만 연결 후보로 인정한다. 전체 최초 PID 목록을 받은 뒤 단일 연결 가능 PoB는 자동 연결하고 복수 후보는 사용자 선택을 받는다. 후보 PID만으로 복수 PoB 중 하나를 자동 선택하지 않는다.
- 선택된 PoB의 유효한 저장 빌드 경로만 이후 요청에 전달하고, 경로가 사라지거나 파일을 읽을 수 없으면 이전 빌드를 현재 빌드처럼 사용하지 않는다.
- 진행 중 요청과 다른 저장 빌드 분석은 기본 맥락을 바꾸지 않는다.
- 선택된 PoB가 종료되면 Agent도 종료하고 다른 프로세스로 자동 전환하지 않는다.
