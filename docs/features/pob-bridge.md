# PoB 브리지

> 상태: 제품 동작은 합의됨. Electron 메인 프로세스의 상태 파일 수신과 디렉터리 감시는 구현됨. PoB 송신 코드와 감시자 연동은 아직 구현되지 않았다.

이 문서는 별도 앱인 PoB Agent가 Path of Building(PoB)과 함께 실행되고, 하나의 PoB 프로세스에 연결되어 해당 프로세스의 활성 저장 빌드를 따라가는 방식을 정의한다. 필요한 최소 PoB 소스 변경은 [PoB 측 브리지 변경 사항](pob-bridge-pob-side.md)에 명시되어 있다. 창과 채팅 동작은 [에이전트 창](agent-window.md)에 명시되어 있다.

이 문서는 사용자에게 보이는 동작 중 합의된 부분과 추가 조사가 필요한 구현 세부 사항을 구분한다. 상태 파일 형식과 위치는 아래 구현 사항을 따르며, 프로세스 감시 API와 PoB 훅은 아직 정하지 않았다.

## 제품 요구 사항

### 목표

PoB가 실행되면 별도 감시자가 에이전트를 실행하고 PoB 프로세스 정보를 전달한다. 에이전트는 선택된 PoB 프로세스 하나의 활성 저장 빌드를 따라간다. 사용자는 UI에서 빌드를 고르지 않고 자연어로 해당 빌드에 관해 질문할 수 있다. 다른 저장 빌드를 분석하려면 질문에 빌드명을 지정한다.

### 범위에 포함

- 에이전트 앱과 PoB 프로세스 감시자는 별도의 프로세스다.
- 감시자는 Windows 로그인 시 자동으로 시작하거나 수동으로 시작할 수 있다. 기본값은 로그인 시 자동 실행이다.
- 감시자는 PoB 프로세스를 감지하고 에이전트를 실행한 뒤 프로세스 식별자를 전달한다. 선택된 PoB가 없는 에이전트가 이미 실행 중이면 중복으로 실행하지 않고 최초 후보를 기존 인스턴스에 전달한다. PoB 하나가 선택된 뒤에는 이후 실행되는 PoB를 무시한다.
- 최초 연결 시 사용 가능한 PoB 프로세스가 하나면 에이전트가 자동으로 연결한다. 여러 개면 사용자가 에이전트가 따라갈 프로세스를 선택한다.
- PoB 프로세스를 선택한 뒤에는 나중에 실행되는 PoB가 해당 프로세스를 자동으로 대체하거나, 활성 맥락에 빌드 경로 업데이트를 보내지 않는다.
- 에이전트는 선택된 PoB 프로세스를 감시한다. 해당 프로세스가 종료되면 에이전트도 종료된다. 현재 버전은 실행 중인 다른 PoB로 자동 전환하지 않는다. 사용자는 에이전트를 다시 열어 프로세스를 선택할 수 있다.
- 선택된 PoB의 활성 저장 빌드 파일 경로가 기본 빌드 맥락이다. PoB 측 코드는 시작 시 현재 선택된 빌드를 알리고, 사용자가 다른 빌드를 선택할 때 경로를 갱신한다. 빌드 내부 값만 수정할 때는 통신 파일을 갱신하지 않는다. 에이전트는 빌드 파일을 로컬에서 읽고 경로에서 화면에 표시할 빌드명을 가져온다.
- 에이전트 UI는 사용자에게 빌드 파일을 선택하도록 요청하지 않는다. “이 빌드”, “우리 빌드”와 같은 자연어 표현은 선택된 PoB의 현재 저장 빌드를 가리킨다.
- 사용자가 다른 빌드명을 명시하면 에이전트는 설정된 빌드 폴더에서 저장된 빌드를 검색한다. 일치 항목이 하나면 바로 분석하고, 여러 개면 사용자 확인을 받는다. 일치 항목이 없으면 찾지 못했다고 알리고 사용자에게 이름을 확인해 달라고 요청한다. 이 검색은 해당 요청에만 적용되며, 선택된 PoB의 활성 빌드 맥락을 바꾸지 않는다.
- 분석할 수 있는 대상은 저장된 빌드 파일뿐이다. 에이전트는 저장되지 않은 PoB 상태를 사용하지 않는다. 선택된 빌드에 저장 경로가 없거나 파일을 찾을 수 없거나 읽을 수 없으면 사용할 수 없는 빌드라고 알리고, 이전 빌드를 현재 빌드인 것처럼 조용히 사용하지 않는다.
- 연결은 활성 저장 빌드의 경로만 전달한다. PoB 메모리, 빌드 내용, 계산 결과 또는 저장되지 않은 수정 사항을 읽거나 전송하지 않는다.

### 범위에서 제외

- 선택된 PoB 프로세스가 종료될 때 다른 PoB로 자동 전환하는 기능
- 연결 코드를 통해 PoB 메모리, UI, 저장되지 않은 상태, 빌드 내용 또는 계산값을 읽는 기능
- PoB UI 자동화, 빌드 편집 또는 빌드 저장
- PoE2 지원
- 위 빌드 맥락 규칙을 넘어서는 채팅 UI 및 요청 동작. [에이전트 창](agent-window.md)을 참고한다.
- MCP 도구, LuaJIT 계산 세부 사항 및 모델 연동

### 사용자 흐름

1. 감시자는 기본적으로 Windows 로그인 시 시작한다. 사용자는 시작 설정을 수동 실행으로 바꿀 수 있다.
2. 감시자는 PoB를 감지해 프로세스 정보를 전달하면서 에이전트를 실행한다. 선택된 PoB가 없는 에이전트가 이미 열려 있으면 감시자는 후보를 기존 인스턴스에 보낸다.
3. 최초 연결에 사용 가능한 PoB가 하나면 에이전트가 연결한다. 여러 개면 에이전트가 사용자에게 하나를 선택하도록 요청한다.
4. 에이전트는 선택된 프로세스의 활성 저장 빌드 경로를 따라간다. 해당 PoB에서 다른 저장 빌드를 선택하면 에이전트는 이후 요청에 사용할 기본 맥락을 갱신한다.
5. 사용자는 자연어로 현재 빌드에 관해 질문할 수 있다. 다른 빌드에 관해 질문하려면 빌드명을 지정한다. 에이전트는 설정된 저장 빌드 폴더에서 검색해 위의 일치 규칙을 적용한다.
6. 이후 실행되는 PoB는 선택된 프로세스를 대체하지 않는다. 선택된 프로세스가 종료되면 에이전트도 다른 실행 중인 PoB로 전환하지 않고 종료된다.

### 완료 기준

- 감시자는 Windows 로그인 시 시작과 수동 실행을 모두 지원하며, 기본값은 로그인 시 자동 실행이다.
- PoB가 실행되면 에이전트가 시작되고 PoB 프로세스 식별자가 전달된다. 선택된 PoB가 없는 에이전트가 이미 실행 중이면 중복 프로세스 없이 최초 후보를 받는다. 연결 후에는 이후 PoB 실행을 무시한다.
- 사용 가능한 PoB가 하나면 자동 연결하고, 여러 개면 사용자가 선택해야 한다.
- 에이전트는 선택된 PoB에서 온 빌드 경로 업데이트만 수락하고 저장된 파일을 로컬에서 읽는다.
- PoB 빌드가 바뀌면 이후 요청에 반영된다. 이미 진행 중인 요청은 시작할 때 사용한 빌드 경로를 유지한다.
- 현재 활성 PoB 빌드는 생략된 빌드 참조의 기본 맥락이다. 명시적으로 지정한 다른 빌드는 해당 요청에만 적용하며 기본 맥락을 대체하지 않는다.
- 다른 빌드 검색 결과가 하나면 바로 분석하고, 여러 개면 확인을 받으며, 결과가 없으면 사용자에게 이름을 확인해 달라고 요청한다.
- 저장되지 않았거나, 없거나, 읽을 수 없는 빌드를 이전 빌드인 것처럼 조용히 나타내지 않는다.
- 선택된 PoB가 종료되면 에이전트도 종료되며, 실행 중인 다른 PoB에 자동 연결하지 않는다.
- 연결 코드는 저장 파일 경로만 전송하며 빌드 데이터나 계산 결과는 전송하지 않는다.

## 시스템별 책임

| 구성 요소 | 책임 |
| --- | --- |
| PoB 프로세스 감시자 | 사용자 시작 설정에 따라 실행되고, PoB 프로세스를 감지하며, 에이전트를 시작하고, 프로세스 정보를 전달한다 |
| 에이전트 앱 | 에이전트를 하나만 실행하도록 보장하고, 후보가 여러 개면 PoB 프로세스를 선택하며, 프로세스 실행 상태를 추적하고 활성 빌드 맥락을 관리한다 |
| PoB 측 브리지 코드 | 활성 저장 빌드가 바뀔 때 해당 빌드 파일 경로를 알린다 |
| 로컬 빌드 도구 | 지정된 저장 빌드를 검색하고 분석을 위해 선택된 파일을 로컬에서 읽는다 |

## 상태 파일 구현

- Agent는 `app.getPath('userData')/pob-bridge` 디렉터리를 만들고 감시한다. Windows 기본 경로는 `%APPDATA%\pob-agent\pob-bridge`이며, 사용자 이름이나 OneDrive 위치를 코드에 고정하지 않는다.
- PoB는 프로세스별 `<PID>.json` 파일에 PID와 활성 저장 빌드 경로를 기록한다. 형식은 `{"pid": 1234, "buildPath": "C:\\...\\build.xml"}`이며, 저장된 빌드가 없으면 `buildPath`는 `null`이다.
- Agent는 시작 시 디렉터리를 읽고, `fs.watch` 변경 알림이 오면 상태 파일을 다시 읽는다. 빌드 XML 자체는 감시하지 않는다.
- Agent는 상태 파일에 기록된 PID가 종료되면 해당 파일을 정리하고 대상을 제거한다. 선택된 PID 종료 시 기존 동작대로 Agent도 종료한다.
- Windows 파일 변경 알림은 놓칠 수 있다. 알림이 누락되면 다음 파일 변경이나 Agent 재시작 때까지 상태 반영이 늦어질 수 있다.

## 미결정 구현 사항

- 감시자가 사용할 Windows 프로세스 감시 API와 PoB 프로세스 식별 규칙
- 감시자와 에이전트가 프로세스 식별자를 전달하고, 기존 PoB 인스턴스를 열거하며, 여러 프로세스가 실행 중일 때 선택 화면을 표시하는 방법
- 실행 중인 PoB가 없을 때 에이전트를 수동으로 실행하면 어떻게 동작할지
- 현재 프로세스가 실행 중인 동안 최초 연결 후 에이전트에서 선택된 PoB를 변경할 수 있는지 여부
- 선택된 PoB가 열린 상태에서 사용자가 에이전트를 닫으면 어떻게 동작할지
- PoB 측에서 파일 경로와 파일명을 구하는 훅 위치
- PoB 상태 파일 기록 중 Agent가 부분 파일을 읽지 않도록 하는 갱신 방법
- 설정된 빌드 폴더를 가져오고 빌드명을 일치시키는 방법
- PoB 호환성, 연결 코드 설치·업데이트·백업·제거·복구 방법
- 로그인 자동 시작 설정을 설치하고 변경하는 방법

구현 세부 사항은 분리된 개발용 복사본과 에이전트에서 검증하기 전까지 제안 상태로 둔다.
