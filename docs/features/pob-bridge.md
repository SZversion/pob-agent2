# PoB Bridge

> 상태: 제품 요구사항 합의, 구현 설계 초안. 기능은 아직 구현되지 않았고 미결정 구현 항목이 남아 있습니다.

## 1. 문서 목적과 범위

이 문서는 설치된 Path of Building (PoB)과 분리된 PoB Agent가 연결되는 기능을 정의합니다. PoB 연결, Agent 단일 실행과 종료, 활성 저장 빌드 파일 경로 전달만 다룹니다.

요구사항과 구현 설계를 구별합니다. **PRD**는 사용자에게 보장할 동작이고, **SDD**는 현재 합의된 경계와 제안하는 구현 방향입니다. IPC 전송 방식이나 PoB 코드 수정 지점처럼 합의되지 않은 사항은 확정하지 않습니다.

## 2. PRD: 제품 요구사항

### 목표

사용자가 Agent에서 PoB 연동을 한 번 설정하면, PoB 실행 시 Agent가 함께 시작되고 PoB에서 현재 선택한 저장 빌드 파일을 자동으로 사용하게 합니다. 사용자가 빌드 파일을 매번 Agent에 다시 지정하지 않아도 되는 것이 목적입니다.

### 사용자와 문제

PoE1 빌드를 PoB에서 관리하며, 해당 빌드의 딜 메커니즘을 Agent에 질문하려는 사용자입니다. Agent가 PoB에서 선택한 빌드 파일을 알 수 있어야 하지만, PoB의 미저장 메모리 상태나 화면을 읽을 필요는 없습니다.

### In Scope

- Agent 설정에서 사용자가 PoB 연동을 시작합니다.
- 연동 과정은 설치된 PoB에 최소 연결 코드를 적용합니다.
- PoB가 시작될 때 Agent 실행을 요청하고, 요청을 보낸 PoB의 프로세스 ID (PID)를 전달합니다.
- Agent는 사용자 세션에서 한 번에 하나만 실행됩니다. 이름 있는 Windows mutex로 중복 실행을 막습니다.
- PoB가 요청해 시작한 Agent는 요청한 PoB에 연결합니다. Agent가 이미 실행 중이면 두 번째 Agent를 만들지 않고 실행 중인 Agent에 인스턴스 정보를 전달합니다.
- Agent 수동 실행 시 실행 중 PoB가 하나면 자동 연결하고, 여러 개면 사용자가 Agent 창 하단 선택기에서 대상을 고릅니다. 실행 중인 PoB가 없으면 연결 해제 상태로 시작하며, 이후 PoB가 시작되면 자동 연결합니다.
- 연결 대상은 Agent가 실행되는 동안 언제든 바꿀 수 있습니다. 이미 연결된 상태에서 다른 PoB가 시작되어도 자동 전환하지 않습니다.
- Agent는 선택된 PoB 프로세스가 종료되면 정리 후 종료합니다. 다른 실행 중 PoB로 자동 전환하지 않습니다.
- 연결된 PoB에서 활성 빌드 선택이 바뀔 때 해당 저장 빌드 파일의 경로만 Agent에 전달합니다.
- Agent는 해당 경로를 로컬에서 읽습니다. 빌드 파일 내용이나 계산값을 PoB 연동 코드가 Agent에 전달하지 않습니다.
- 저장되지 않은 변경사항은 사용하지 않습니다.

### Out of Scope

- PoB 연결 대상의 순차 대기열, 선택된 인스턴스 종료 후 다른 PoB로 자동 전환.
- PoB 프로세스 메모리, UI 화면 또는 미저장 상태에서 빌드 내용이나 계산값 가져오기.
- PoB UI 자동 조작, 빌드 수정 또는 저장.
- Agent 창의 UI와 채팅 세부 동작. [Agent 창 기능 정의](agent-window.md)에서 다룹니다.
- MCP 도구, LuaJIT 계산 엔진, 모델 연결, 인터넷 검색의 세부 설계. 별도 문서에서 다룹니다.
- PoE2 지원.

### 사용자 흐름

1. 사용자가 Agent 설정에서 PoB 연동을 선택합니다.
2. Agent가 설치된 PoB에 연결 코드를 적용합니다.
3. 사용자가 연동된 PoB를 실행합니다.
4. PoB 연결 코드가 Agent 실행을 요청하며 자신의 PID를 전달합니다.
5. Agent가 mutex를 먼저 확보하면 요청한 PoB와 연결하고 Agent 창과 MCP 서버를 준비합니다. 이미 Agent가 실행 중이면 기존 Agent에 새 PoB 인스턴스 정보를 전달하고 새 Agent는 종료합니다.
6. Agent를 수동 실행하면 PoB가 하나일 때 자동 연결하고, 여러 개일 때는 사용자가 창 하단 선택기에서 대상을 고릅니다. PoB가 없으면 연결 해제 상태로 열리고 나중에 시작된 PoB에 자동 연결합니다.
7. Agent 연결 중 다른 PoB가 시작되어도 연결은 유지됩니다. 사용자는 선택기에서 연결을 바꿀 수 있으며, 새 연결이 성공한 경우에만 기존 연결을 해제하고 전환합니다.
8. 연결된 PoB에서 활성 빌드 선택이 바뀌면 연결 코드가 새 저장 파일 경로를 Agent에 알립니다. Agent는 해당 파일을 로컬에서 읽습니다.
9. 현재 연결된 PoB가 종료되면 Agent는 정리 후 종료합니다. 다른 PoB가 실행 중이어도 연결을 넘기지 않습니다.

### 완료 기준

**로컬 자동 검증**

- Agent 시작 요청에 PID가 전달되고, Agent가 선택한 소유 PID를 내부 상태에서 확인할 수 있습니다.
- 첫 요청으로 Agent가 실행된 뒤 두 번째 시작 요청은 Agent를 중복 실행하지 않고 기존 Agent에 해당 PoB 인스턴스를 등록합니다.
- 수동 실행 시 PoB가 없으면 연결 해제, 하나면 자동 연결, 여러 개면 사용자 선택 상태가 됩니다. PoB가 없는 상태에서 나중에 시작된 인스턴스는 자동 연결됩니다.
- 연결 대상 변경은 새 대상 연결 성공 후에만 적용되며, 연결 실패 시 기존 연결이 유지됩니다.
- Agent는 소유 PID 프로세스의 종료만 기다립니다. 해당 프로세스 종료 시 정리 및 종료 흐름이 실행됩니다.
- 연결 코드에서 Agent로 전송되는 빌드 정보는 경로만 포함합니다. 빌드 XML, 빌드 내용, 계산 결과는 포함하지 않습니다.
- 활성 빌드 경로가 바뀌면 Agent의 현재 경로가 갱신되고, 이전 경로의 결과를 새 빌드 결과인 것처럼 사용하지 않습니다.
- 미저장 변경사항은 입력으로 전달되지 않습니다.
- 잘못된 PID, 전송 실패, 경로 누락·접근 실패를 성공이나 다른 빌드로 조용히 대체하지 않고 식별 가능한 실패 상태로 처리합니다.

**실제 PoB 연동 QA**

- 지원 대상으로 정한 PoB 설치본에 연동을 적용한 후 PoB 시작과 함께 Agent 한 개가 실행됩니다.
- PoB를 두 개 실행할 때 먼저 연결된 인스턴스만 Agent 소유자로 유지되고, 두 번째 인스턴스는 연결 요청을 큐에 넣지 않습니다.
- 두 PoB가 모두 실행 중일 때 소유 PoB를 종료하면 Agent가 종료되며, 남은 PoB로 자동 연결되지 않습니다.
- 연결된 PoB에서 저장 빌드 선택을 전환하면 Agent가 새 저장 파일 경로를 받습니다. Agent는 빌드 파일을 로컬에서 읽습니다.
- 미저장 편집 내용은 Agent의 입력에 포함되지 않습니다.
- PoB 연동 오류와 지원되지 않는 PoB 버전에서 사용자가 연결 실패를 알 수 있습니다.

실제 PoB 설치본과 지원 버전이 정해지기 전에는 실제 연동 QA 완료를 주장할 수 없습니다.

## 3. SDD: 시스템 설계 초안

### 구성요소와 책임

| 구성요소 | 책임 |
| --- | --- |
| PoB 연결 코드 | PoB 시작 시 Agent에 시작을 요청하고 PID를 전달하며, 활성 빌드 선택 변경 시 저장 파일 경로만 알림 |
| Agent 시작 절차 | mutex를 UI 및 MCP 초기화보다 먼저 확보하고, 중복 실행 요청을 기존 Agent에 전달 |
| Agent 연결 관리자 | PoB 인스턴스 목록과 선택된 PID를 관리하고, 대상 변경 및 선택된 프로세스 종료를 처리하며 경로 알림을 받음 |
| 로컬 IPC | PoB 연결 코드와 Agent 사이에서 PID/경로 이벤트를 전달. 구체 프로토콜은 미결정 |
| 빌드 입력 처리기 | 경로의 저장 파일을 로컬에서 열어 이후 계산 흐름에 제공 |

### 시작·단일 실행·종료 방식

1. Agent 설정의 연동 작업이 설치된 PoB에 연결 코드를 적용합니다. 연결 코드가 적용되는 정확한 파일·확장 지점과 복구 방법은 미결정입니다.
2. PoB 연결 코드는 Agent 실행 파일을 시작하며 요청한 PoB PID를 전달합니다. 프로세스 ID 전달은 합의됐지만 명령줄 인자 형식은 미정입니다.
3. Agent는 이름 있는 Windows mutex를 가장 먼저 검사·확보합니다. 확보한 실행은 UI, MCP 및 연결 관리자를 시작합니다.
4. mutex가 이미 있으면 기존 Agent에 새 PoB 인스턴스 정보를 로컬 IPC로 전달하고, 새로 시작된 프로세스는 종료합니다. 이 이벤트는 기존 연결을 자동으로 바꾸지 않습니다.
5. Agent 수동 실행 시 실행 중인 PoB를 조사합니다. 0개면 연결 해제 상태로 시작하고 이후 시작 이벤트를 기다립니다. 1개면 자동 연결합니다. 2개 이상이면 창의 선택기에서 사용자가 대상을 정합니다.
6. 연결된 상태에서는 새 인스턴스를 선택기 옵션에 추가하되 자동 전환하지 않습니다. 사용자가 대상을 바꾸면 새 대상의 연결·초기 상태 확인을 먼저 수행하고 성공한 경우에만 기존 대상을 해제합니다. 실패하면 기존 연결을 유지하고 오류를 표시합니다.
7. 현재 선택된 PoB 프로세스 종료가 확인되면 Agent가 IPC, MCP 및 UI 자원을 정리한 뒤 종료합니다. 다른 PoB 프로세스를 승격하지 않습니다.

### 활성 빌드 경로 전달

- PoB 연결 코드는 활성 빌드 선택 변경 시 경로 이벤트를 보냅니다.
- 연결 코드는 경로만 전송합니다. 파일 내용, XML, PoB 메모리 상태, 계산값은 전송하지 않습니다.
- Agent는 이벤트의 경로를 로컬에서 검증하고 파일을 읽습니다. 읽을 수 없거나 유효하지 않으면 현재 빌드 입력을 정상 갱신한 것처럼 취급하지 않습니다.
- 저장되지 않은 변경사항은 PoB 메모리에서 추출하지 않습니다. 사용자가 저장한 뒤의 실제 파일을 Agent가 읽을 수 있습니다.
- 연결 대상 인스턴스의 이벤트만 수락해야 합니다. PID와 IPC 발신자를 연결하는 인증·검증 방식은 미결정입니다.

### IPC 및 프로세스 경계

초기 Agent 실행은 PoB PID를 전달하는 경로를 사용하고, 실행 후 빌드 변경을 알리는 통신은 로컬 IPC가 필요합니다. Windows named pipe는 후보지만 아직 선택되지 않았습니다. 전송 규격은 최소한 이벤트 종류, 연결 PID, 활성 파일 경로, 오류 응답을 정의해야 하며, 빌드 내용은 포함하지 않아야 합니다.

mutex는 Agent 프로세스 중복 방지에만 사용합니다. 연결 소유권 판별이나 빌드 경로 전송을 대신하지 않습니다. PID는 PoB 프로세스 수명 감지에 사용하고, IPC 발신자 검증은 별도 설계가 필요합니다.

### 오류와 사용자 상태

- PoB 연동 코드가 없거나 시작에 실패하면 Agent가 실행되지 않거나 연결되지 않은 상태를 사용자에게 알립니다.
- mutex가 이미 있으면 두 번째 Agent를 만들지 않고 새 PoB 인스턴스 정보를 기존 Agent에 전달합니다.
- PID가 유효하지 않거나 프로세스 핸들을 열 수 없으면 연결 실패로 처리하고 다른 프로세스를 추측해 연결하지 않습니다.
- IPC 연결이 끊기거나 잘못된 인스턴스의 이벤트가 오면 이를 기록·표시하고 해당 빌드 경로를 현재 값으로 채택하지 않습니다.
- 빌드 경로가 없거나 파일 접근이 실패하면 이전/다른 빌드 결과를 새 빌드 결과인 것처럼 사용하지 않습니다.
- PoB 업데이트로 연결 코드가 깨질 수 있습니다. 연결 호환성 확인과 재적용·제거 절차가 정해지기 전에는 업데이트 후 동작을 보장하지 않습니다.

### 테스트와 관찰 가능성

- 외부 PoB 없이 mutex 중복 실행 규칙, PID 상태 처리, IPC 메시지 스키마와 오류 응답을 단위 테스트합니다.
- 가짜 프로세스와 테스트용 IPC를 사용해 시작 → 경로 변경 → 종료 흐름을 반복 검증합니다.
- Windows 통합 테스트에서 이름 있는 mutex, 중복 실행 시 기존 Agent로 전달, 프로세스 종료 대기를 확인합니다.
- 실제 PoB QA에서는 지원 버전별 연결 코드 적용, PID 전달, 두 인스턴스 경계, 저장 빌드 선택과 미저장 변경 경계를 확인합니다.
- 로그는 연결/종료/오류 이벤트와 단계별 성공 여부를 진단할 수 있어야 합니다. 빌드 내용이나 자격 증명은 기록하지 않습니다.

## 4. 미결정 사항

- PoB 연결 코드를 설치·업데이트·제거·복구하는 절차와 수정할 PoB 파일/확장 지점.
- PoB와 Agent가 지원할 버전 및 호환성 검사 방법.
- Agent 시작 시 PID 전달 형식과 기존 Agent에 PoB 인스턴스 정보를 전달하는 방식.
- 빌드 경로 변경 이벤트에 사용할 IPC(Windows named pipe 등), 메시지 형식, 연결 인증·발신자 검증.
- PoB에서 빌드를 선택했지만 아직 저장 경로가 없을 때의 UX.
- 동일한 선택 빌드를 저장해 파일 내용만 바뀐 경우 Agent에 새로고침을 알릴지, Agent가 언제 파일을 다시 읽을지.
- 수동 실행 시 실행 중 PoB 인스턴스 목록을 탐색하는 방식과, 목록 조회 실패 시 UX.
- mutex 이름과 사용자 세션 범위, 권한 및 비정상 종료 시 동작.
