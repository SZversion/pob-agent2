# PoB 프로세스 선택기

> 상태: 제품 동작 합의. 감지는 [PoB 프로세스 감시자](pob-watcher.md), 상태 파일 수신과 연결은 [Agent 측 브리지](pob-bridge.md)를 따릅니다.

## 목적과 범위

에이전트가 따라갈 실행 중인 PoB 프로세스를 선택하는 동작을 정의합니다. 이 선택기는 빌드 파일을 고르지 않습니다. 선택된 PoB의 현재 저장 빌드 경로와 빌드 분석 규칙은 [PoB 브리지](pob-bridge.md), 창 전체 동작은 [Agent 창 기능](agent-window.md)에 정의합니다.

## 사용자 동작

- 에이전트는 한 번에 하나의 PoB 프로세스에 연결됩니다.
- Agent를 수동 실행했을 때 PoB가 없으면 연결 해제 상태로 대기하고, 이후 PoB가 실행되면 자동으로 연결한다.
- 감시자가 확인한 PID와 상태 파일이 일치하는 PoB가 하나면 자동 연결하고, 여러 개면 항상 사용자가 연결할 프로세스를 선택한다. 감시자가 시작 요청과 함께 특정 PID를 전달해도 후보가 여러 개면 해당 PID에 자동 연결하지 않는다.
- 브리지가 설치되지 않은 경우 연결 버튼을 눌러 설치 폴더를 선택하고 재시작을 안내하는 흐름은 [브리지 설치](pob-bridge-install.md)를 따른다.
- 하단 선택기는 선택된 PoB의 현재 저장 빌드명을 표시합니다. 활성 저장 빌드가 없으면 `PoB`를 표시합니다. 사용자가 빌드 파일을 직접 선택하는 UI는 제공하지 않습니다.
- 선택 가능한 PoB가 하나면 빌드명만 표시하고 펼침 화살표를 숨깁니다. 여러 개면 펼침 화살표를 표시하고 선택 목록에 연결 가능한 프로세스를 나열합니다. 빌드명이 중복되면 프로세스 시작 시각을 함께 표시해 구분합니다.
- 최초 연결 후 대상은 고정되며, UI와 IPC 모두 다른 프로세스로 전환하는 것을 거부합니다.
- 대상이 선택된 뒤 시작된 다른 PoB는 자동으로 현재 연결을 대체하지 않습니다. 선택된 PoB가 종료되면 에이전트를 종료하며 다른 프로세스로 자동 승계하지 않습니다.
- “이 빌드”, “우리 빌드”는 선택된 PoB의 현재 저장 빌드를 뜻합니다. 다른 빌드는 사용자가 자연어로 지정하며, 해당 요청에 한해 분석합니다. 빌드 파일 경로와 검색 규칙은 PoB 브리지 문서를 따릅니다.

## 책임 경계

- Electron main이 PoB 프로세스 후보와 현재 선택을 소유하고 연결 전환을 검증합니다.
- 렌더러는 범위가 좁은 preload/IPC API를 통해 후보를 표시하고 선택 요청을 보냅니다.
- PoB 프로세스 감지와 PID 전달은 [감시자](pob-watcher.md), 활성 저장 빌드 경로 수신은 [Agent 측 브리지](pob-bridge.md)에서 정의합니다. 이 문서는 통신 프로토콜이나 파일 형식을 정의하지 않습니다.

## 완료 기준

- Agent가 PoB 없이 시작하면 연결 해제 상태로 대기하고, PoB 실행 후 연결됩니다.
- 브리지가 설치된 PoB 후보가 하나면 자동 연결되고, 여러 개면 사용자가 선택합니다.
- 브리지가 없을 때 연결 버튼으로 설치 폴더를 지정하면 PoB 파일을 수정하고 재시작을 안내합니다.
- 선택기는 빌드 파일이 아니라 PoB 프로세스를 선택합니다.
- 선택 가능한 PoB가 하나면 펼침 화살표가 없고, 여러 개면 목록을 펼칠 수 있습니다.
- 현재 선택된 프로세스의 저장 빌드명 또는 `PoB`가 표시됩니다.
- 중복 빌드명은 프로세스 시작 시각으로 구분됩니다.
- 최초 연결 후 다른 프로세스 선택 요청은 거부됩니다.
- 선택된 PoB가 종료되면 에이전트가 종료되고 다른 PoB로 자동 승계하지 않습니다.
