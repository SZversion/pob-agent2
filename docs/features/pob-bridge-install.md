# PoB 브리지 설치

> 상태: 사용자 흐름과 적용 범위 합의. Agent의 설치본 자동 수정 기능은 아직 구현되지 않았다.

이 문서는 Agent가 사용자가 선택한 PoB 설치본에 [PoB 측 상태 송신 코드](pob-side.md)를 적용하는 일회성 준비 절차를 정의한다. 실행 중 PoB 감지와 Agent 실행은 [감시자](pob-watcher.md), 상태 파일 수신은 [Agent 측 브리지](pob-bridge.md)를 따른다.

## 사용자 흐름

1. 브리지가 설치되지 않은 PoB와 연결하려는 사용자가 Agent의 연결 버튼을 누른다.
2. 사용자가 PoB 설치 폴더를 선택하면 Agent가 해당 설치본에 필요한 송신 코드를 적용한다. 사용자가 빌드 파일을 직접 선택하지 않는다.
3. Agent는 PoB를 다시 시작해야 새 코드가 동작한다고 안내한다. 실행 중인 PoB를 강제로 종료하지 않는다.
4. 재시작한 PoB가 상태 파일을 기록하면 Agent가 감시자가 확인한 PID와 대조해 연결 후보로 사용한다.

## 변경 범위

- 설치본에는 개발용 복사본과 동일한 상태 파일 송신 구현만 적용한다. 변경 대상은 `PobAgentBridgeDraft` 모듈 추가와 `Modules/Main.lua`의 로드·호출 연결이다.
- 설치 기능은 위 변경과 필요한 설치 상태 확인 외의 PoB 파일이나 동작을 수정하지 않는다. PoB 메모리, 빌드 내용, 계산 결과를 Agent로 보내는 코드를 추가하지 않는다.
- PoB 업데이트 후 연결 코드를 다시 적용해야 할 수 있다. 재적용 방식은 아직 결정되지 않았다.

## 완료 기준

- 연결 버튼에서 PoB 설치 폴더를 선택하면 지원하는 설치본에 송신 코드를 적용하고 재시작 필요를 알린다.
- Agent는 PoB를 강제로 종료하거나 빌드를 수정·저장하지 않는다.
- 재시작 후 PoB가 PID와 활성 저장 빌드 경로만 상태 파일에 기록하고 Agent가 해당 파일을 읽는다.
- 설치할 수 없는 폴더나 적용 실패를 연결 성공으로 표시하지 않는다.

## 구현 전에 결정할 사항

- 지원할 PoB 버전 판별 기준, 설치본에서 수정할 파일의 정확한 상대 경로와 `Modules/Main.lua`에 연결 코드를 넣을 기준 위치
- 원본 파일 백업·복구·제거, 이미 수정된 설치본 처리 및 PoB 업데이트 후 재적용 규칙
- 쓰기 권한이 없는 설치 폴더와 지원하지 않는 폴더에 대한 안내, 설치 상태 검사와 실패 처리 세부

현재 송신 코드는 Git에서 추적하지 않는 `.pob/Path of Building Community` 개발용 복사본에만 적용되어 있다. 설치본 자동 적용과 패키징된 Agent와의 통합 검증은 남아 있다.
