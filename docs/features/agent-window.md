# Agent 창 기능

> 상태: 제품 요구사항 합의, 구현 설계 초안. 기능은 아직 구현되지 않았고 모델 연결 프로토콜 등 미결정 사항이 남아 있습니다.

## 1. 문서 목적과 범위

PoB Agent의 별도 데스크톱 창, 채팅, 준비 상태, PoB 연결 대상 선택 및 설정 화면을 정의합니다. PoB 프로세스 연결과 빌드 경로 이벤트의 상세는 [PoB와 Agent 연결 기능](pob-agent-connection.md)을, 계산 도구 경계는 [MCP 실행 및 계산기 호출 방식](../MCP.md)을 따릅니다.

## 2. PRD: 제품 요구사항

### 목표

사용자가 PoB 빌드에 대해 질문하고 답변을 스트리밍으로 확인하는 전용 창을 제공합니다. Agent는 PoB 및 로컬 Python MCP 프로세스와 함께 동작하지만, MCP 환경과 UI는 별도 프로세스 경계로 유지합니다.

### In Scope

- 기술 스택은 Electron, React, TypeScript, Vite입니다. Electron은 데스크톱 앱 셸과 메인 프로세스를 제공하며, Vite는 React 렌더러의 개발 서버와 빌드 도구로 사용합니다.
- Electron 메인 프로세스가 앱 수명주기, PoB 연결 관리자, Python MCP 프로세스 시작·종료와 모델 연결을 관리합니다. React 렌더러는 채팅 UI를 표시하고 좁은 preload/IPC 인터페이스를 통해 필요한 동작만 요청합니다.
- Agent 창은 PoB가 Agent 시작을 요청할 때 자동으로 열립니다. 수동 실행 시에도 Agent 창을 엽니다.
- Agent는 사용자 세션에서 하나만 실행됩니다. 이미 실행 중일 때 PoB가 시작을 요청하면 새 인스턴스를 띄우지 않고 실행 중인 Agent에 연결 요청을 전달합니다.
- Agent 창은 기본 960×720, 크기 조절 가능하며 창 크기는 저장하지 않습니다.
- Agent 창을 닫으면 Agent 프로세스가 종료됩니다. 연결된 PoB를 닫아도 Agent가 종료됩니다. Agent를 수동으로 종료한 뒤에는 따로 실행할 수 있고, PoB를 종료 후 다시 실행하면 Agent가 다시 함께 시작됩니다.
- 채팅 기록과 대기열은 메모리에만 둡니다. Agent 창 또는 앱을 닫으면 보존하지 않습니다.
- 화면은 어두운 톤입니다. 상단에 `PoB 연결됨` 상태를 표시합니다. 채팅은 중앙 영역에 두고, 하단 입력 영역에는 원형 배경의 화살표 전송 버튼을 둡니다.
- 하단 왼쪽의 PoB 선택기는 현재 연결된 빌드명을 표시하고, 선택 메뉴에서 연결 대상을 바꿉니다. 활성 빌드가 없으면 `PoB`로 표시합니다. 하단 오른쪽에는 설정 진입점을 둡니다. 별도의 중복 연결 상태나 별도 현재 빌드 라벨은 표시하지 않습니다.
- 설정 화면은 우선 비어 있는 화면만 제공합니다. 모델 연결 설정 UI는 제공하지 않습니다.
- MCP 서버와 모델 연결이 모두 준비되기 전에는 채팅 입력과 전송을 비활성화하고 채팅 영역에 준비 상태를 표시합니다.
- 준비 실패는 사용자에게 중간 노출하지 않고 자동 재시도합니다. 첫 시도를 포함해 총 3회 실패하면 채팅에 오류를 표시하고 재시도 버튼을 제공합니다. 재시도는 준비 절차를 다시 실행합니다.
- 응답은 스트리밍으로 표시합니다.
- 응답 생성 중 새 프롬프트는 FIFO 대기열에 추가하며, 대기 중인 항목을 각각 삭제할 수 있습니다. 현재 응답이 끝나면 다음 항목을 자동 전송합니다. 대기열 순서 변경은 지원하지 않습니다.
- 요청 실패 시 자동 재시도하지 않습니다. 실패한 사용자 메시지를 실패 상태로 남기고 부분 답변은 미완료로 표시합니다. 실패한 프롬프트를 입력창에 넣어 사용자가 수정하거나 그대로 재전송할 수 있게 합니다. 재전송한 요청은 대기열의 기존 항목보다 먼저 처리합니다. 실패 항목을 삭제하면 대기열 처리를 재개합니다.
- 현재 연결된 PoB 안에서 활성 빌드 경로가 바뀌어도 대화와 대기열을 지우거나 현재 응답을 중단하지 않습니다. 진행 중 요청은 시작 시점의 경로를 사용하고, 다음 요청부터 최신 경로를 사용합니다. 전환 시 현재 답변은 이전 빌드 기준이며 다음 요청부터 새 빌드 기준임을 시스템 메시지로 알립니다.
- PoB 연결 대상 변경은 연결을 유지한 채 새 대상과 연결을 시도합니다. 새 대상 연결 성공 후에만 기존 연결을 끊고 전환합니다. 실패하면 기존 연결과 대화 상태를 유지합니다. 전환 성공 시 대화나 대기열이 있으면 사용자에게 확인을 받고, 확인 후 진행 중 응답을 중지하고 대화와 대기열을 비운 뒤 새 대상으로 전환합니다.

### Out of Scope

- 채팅 기록 또는 대기열의 디스크 저장·복원.
- 설정 화면의 실제 설정 항목 및 모델 연결을 사용자가 변경하는 UI.
- PoB UI 자동 조작, 메모리 접근, 빌드 내용 또는 미저장 변경 접근.
- MCP 서버의 도구, LuaJIT 및 PoB 엔진 내부 구현.
- 창 크기·위치 복원, 여러 대화 세션 및 대화 기록 관리.

## 3. SDD: 구현 방향

### 구성과 프로세스 경계

| 구성요소 | 책임 |
| --- | --- |
| Electron 메인 프로세스 | 단일 실행, 창 수명주기, PoB 연결 선택·전환, MCP 프로세스 및 모델 연결 관리 |
| React 렌더러 | 채팅, 준비·오류 상태, PoB 선택기와 빈 설정 화면 표시 |
| preload/IPC 브리지 | 렌더러에 명시적으로 필요한 최소 API만 제공 |
| Python MCP 서버 | 앱이 `uv`로 실행하고 stdio로 통신하는 별도 프로세스. [MCP 문서](../MCP.md) 참조 |

렌더러에 Node/Electron 전체 권한을 노출하지 않습니다. PoB 연결 및 MCP 프로세스 제어는 메인 프로세스가 소유합니다. 세부 IPC 채널과 모델 호출 프로토콜은 구현 전 별도 설계가 필요합니다.

### 창과 연결 대상 수명주기

- PoB의 시작 요청으로 Agent가 실행되면 요청에 포함된 인스턴스에 연결하고 창을 엽니다. Agent가 이미 실행 중이면 새 프로세스 대신 기존 메인 프로세스에 PoB 연결 이벤트를 전달합니다.
- Agent를 수동 실행할 때 실행 중인 PoB가 0개면 연결 해제 상태로 시작하고, 나중에 시작되는 PoB에 자동 연결합니다. 1개면 자동 연결합니다. 2개 이상이면 사용자가 하단 선택기에서 대상을 선택합니다.
- 수동 선택 목록은 연결 가능한 실행 중 PoB들로 구성합니다. 표시 이름은 현재 빌드명이며 빌드가 없으면 `PoB`입니다. 같은 빌드명이 여러 개면 시작 시간을 함께 표시해 구분합니다.
- 이미 연결된 상태에서 다른 PoB가 시작되어도 자동 전환하지 않습니다. 새 인스턴스는 선택기에 추가됩니다. 연결이 끊긴 상태에서 PoB가 시작되면 해당 인스턴스에 자동 연결합니다.
- 새 연결을 먼저 검증한 뒤 성공했을 때만 기존 연결에서 새 연결로 전환합니다. 연결 실패는 기존 연결을 유지합니다. 새 대상으로 전환할 때 기존 대화/대기열이 있으면 확인을 받고, 진행 중 응답을 중지하고 대화 상태를 초기화합니다.
- 현재 선택된 PoB 프로세스가 종료되면 Agent를 종료합니다. 다른 실행 중 PoB로 자동 승계하지 않습니다.

### 채팅 상태와 준비 절차

- 초기 상태는 준비 중이며 채팅 입력은 비활성화합니다. MCP 서버와 모델 연결이 모두 준비됐을 때만 입력을 활성화합니다.
- 준비 절차는 총 3회 시도하고, 모두 실패하면 채팅 영역에 오류와 재시도 동작을 노출합니다. 사용자에게는 재시도 횟수별 중간 오류를 보이지 않습니다.
- 채팅 메시지, 스트리밍 응답, 요청 상태 및 FIFO 대기열은 앱 메모리에만 유지합니다.
- 응답 생성 중 제출한 프롬프트를 대기열에 넣고, 현재 요청 완료 시 하나씩 보냅니다. 실패하면 큐를 멈추고 실패 항목을 편집 가능한 입력으로 복사합니다. 사용자의 재전송은 큐 앞에서 처리합니다.
- 요청은 전송 순간의 선택된 PoB와 활성 빌드 경로에 묶입니다. 경로 변경은 진행 중 요청의 입력을 바꾸지 않고, 다음 전송부터 새 경로를 사용합니다.

## 4. 완료 기준

- PoB 실행으로 Agent가 자동 시작되고 창이 표시되며, Agent 중복 실행 없이 기존 인스턴스에 연결 이벤트가 전달됩니다.
- 수동 실행의 PoB 0개·1개·여러 개 경우에 각각 연결 해제·자동 연결·사용자 선택 동작이 맞습니다.
- 빌드명 표시, 빌드 없음 표시, 중복 빌드명 구분 및 연결 대상 변경 성공·실패 처리가 요구사항과 일치합니다.
- Agent 창 닫기와 선택된 PoB 종료가 앱 종료로 이어지고, 재실행 시 대화와 대기열은 복원되지 않습니다.
- 준비 전 입력이 차단되고, 준비 실패 시 정확히 세 번 시도한 후 재시도가 제공됩니다.
- 스트리밍, FIFO 큐, 개별 큐 삭제, 실패 정지·편집·재전송 및 다음 요청 자동 진행이 확인됩니다.
- 같은 PoB의 활성 빌드 경로가 바뀌어도 현재 요청은 기존 경로를 사용하고 다음 요청부터 새 경로를 사용합니다.
- Electron 메인 프로세스가 모델 연결과 Python MCP 프로세스를 관리하고, 렌더러에는 좁은 preload/IPC API만 노출됩니다.

## 5. 미결정 사항

- Electron 앱의 구체적인 패키징·배포 도구 및 서명 방식.
- Electron 메인 프로세스에서 모델에 연결하는 프로토콜, 인증 및 스트리밍 규격.
- Python·`uv` 런타임의 개발 및 최종 배포 제공 방식. MCP 문서의 미결정 사항을 따릅니다.
- PoB 연결 이벤트와 프로세스 목록을 Electron 메인 프로세스에서 연동하는 구체 IPC 및 보안 검증.
- 대화/대기열이 있는 상태에서 PoB 전환 확인 UI의 문구와 취소 시 세부 동작.
- 준비 단계별 시간 제한 및 백오프 간격.
