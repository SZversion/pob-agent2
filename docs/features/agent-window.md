# Agent 창 기능

> 상태: 제품 요구사항 합의, 구현 설계 초안. 기능은 아직 구현되지 않았으며 PoB bridge와 모델 연결 세부는 별도 문서에서 다룹니다.

## 1. 문서 목적과 범위

PoB Agent의 별도 데스크톱 창, 채팅, 준비 상태, 다중 PoB 프로세스 선택 및 설정 화면을 정의합니다. PoB 연결과 빌드 경로 전달은 [PoB bridge](pob-bridge.md), 계산 도구 경계는 [MCP 실행 및 계산기 호출 방식](../MCP.md), 패키징과 배포는 [Agent 패키징 및 배포](agent-packaging.md)를 따릅니다.

## 2. PRD: 제품 요구사항

### 목표

사용자가 PoB 빌드에 대해 질문하고 답변을 스트리밍으로 확인하는 전용 창을 제공합니다. Agent는 PoB 및 로컬 Python MCP 프로세스와 함께 동작하지만, MCP 환경과 UI는 별도 프로세스 경계로 유지합니다.

### In Scope

- 기술 스택은 Electron, React, TypeScript, Vite입니다. Electron은 데스크톱 앱 셸과 메인 프로세스를 제공하며, Vite는 React 렌더러의 개발 서버와 빌드 도구로 사용합니다.
- Electron 메인 프로세스가 앱 수명주기, PoB 연결 관리자, Python MCP 프로세스 시작·종료와 모델 연결을 관리합니다. React 렌더러는 채팅 UI를 표시하고 좁은 preload/IPC 인터페이스를 통해 필요한 동작만 요청합니다.
- 별도 PoB 감시자 프로세스가 Windows 로그인 시 자동 실행되며, 사용자는 설정에서 수동 실행 방식으로 변경할 수 있습니다. 로그인 자동 실행이 기본값입니다. 감시자가 PoB 프로세스를 감지하면 Agent를 실행하고 PID를 전달합니다.
- Agent는 사용자 세션에서 하나만 실행됩니다. Agent가 이미 실행 중이지만 연결된 PoB가 없으면 감시자는 중복 실행하지 않고 첫 연결 후보를 기존 Agent에 전달합니다. 이미 연결된 뒤 시작한 PoB는 무시합니다.
- Agent 창은 기본 960×720, 크기 조절 가능하며 창 크기는 저장하지 않습니다.
- Agent 창을 닫으면 Agent 프로세스가 종료됩니다. 연결된 PoB를 닫아도 Agent가 종료됩니다. 연결된 PoB가 종료되어도 다른 실행 중인 PoB로 자동 승계하지 않습니다.
- 채팅 기록과 대기열은 메모리에만 둡니다. Agent 창 또는 앱을 닫으면 보존하지 않습니다.
- 화면은 어두운 톤입니다. 상단에 `PoB 연결됨` 상태를 표시합니다. 채팅은 중앙 영역에 두고, 하단 입력 영역에는 원형 배경의 화살표 전송 버튼을 둡니다.
- 하단 왼쪽에는 연결된 PoB의 현재 저장 빌드명을 표시합니다. 사용자가 빌드 파일을 직접 선택하는 UI는 제공하지 않습니다. 초기 연결 후보가 여러 개면 Agent에서 PoB 프로세스를 고릅니다. 하단 오른쪽에는 설정 진입점을 둡니다.
- 설정 화면에는 감시자의 시작 방식을 로그인 자동 실행 또는 수동 실행으로 선택하는 항목을 둡니다. 로그인 자동 실행이 기본값입니다. 모델 연결 설정 UI는 제공하지 않습니다.
- MCP 서버와 모델 연결이 모두 준비되기 전에는 채팅 입력과 전송을 비활성화하고 채팅 영역에 준비 상태를 표시합니다.
- 각 준비 시도는 MCP와 모델 연결이 준비될 때까지 최대 10초 기다립니다. 제한 시간 안에 준비되지 않으면 0.5초 뒤 재시도하며, 첫 시도를 포함해 총 3회 실패하면 채팅에 오류를 표시하고 재시도 버튼을 제공합니다. 재시도는 전체 준비 절차를 다시 시작합니다. 10초 제한은 사용자 설정에 노출하지 않으며 코드에서 조정할 수 있는 초기값입니다.
- 응답은 스트리밍으로 표시합니다.
- 응답 생성 중 새 프롬프트는 FIFO 대기열에 추가하며, 대기 중인 항목을 각각 삭제할 수 있습니다. 현재 응답이 끝나면 다음 항목을 자동 전송합니다. 대기열 순서 변경은 지원하지 않습니다.
- 요청 실패 시 자동 재시도하지 않습니다. 실패한 사용자 메시지를 실패 상태로 남기고 부분 답변은 미완료로 표시합니다. 실패한 프롬프트를 입력창에 넣어 사용자가 수정하거나 그대로 재전송할 수 있게 합니다. 재전송한 요청은 대기열의 기존 항목보다 먼저 처리합니다. 실패 항목을 삭제하면 대기열 처리를 재개합니다.
- 현재 연결된 PoB 안에서 활성 빌드 경로가 바뀌어도 대화와 대기열을 지우거나 현재 응답을 중단하지 않습니다. 진행 중 요청은 시작 시점의 경로를 사용하고, 다음 요청부터 최신 경로를 사용합니다. 전환 시 현재 답변은 이전 빌드 기준이며 다음 요청부터 새 빌드 기준임을 시스템 메시지로 알립니다.
- “이 빌드”와 “우리 빌드” 같은 표현은 연결된 PoB의 현재 저장 빌드를 뜻합니다. 다른 빌드명을 명시하면 도구가 저장 빌드 폴더에서 검색합니다. 후보가 하나면 해당 요청에서 바로 분석하고, 후보가 여러 개면 사용자 확인을 받으며, 찾지 못하면 구체적인 이름을 요청합니다. 다른 빌드 분석은 PoB의 현재 빌드 맥락을 바꾸지 않습니다.
- 저장된 빌드 파일만 분석합니다. 경로가 없거나 파일을 읽을 수 없으면 사용할 수 없는 빌드임을 표시하고 이전 빌드 결과를 현재 빌드 결과처럼 사용하지 않습니다.

### Out of Scope

- 채팅 기록 또는 대기열의 디스크 저장·복원.
- 모델 연결 설정 UI.
- PoB UI 자동 조작, 메모리 접근, 빌드 내용 또는 미저장 변경 접근.
- MCP 서버의 도구, LuaJIT 및 PoB 엔진 내부 구현.
- 창 크기·위치 복원, 여러 대화 세션 및 대화 기록 관리.

## 3. SDD: 구현 방향

### 구성과 프로세스 경계

| 구성요소 | 책임 |
| --- | --- |
| PoB 감시자 프로세스 | 설정된 시작 방식으로 실행하고 PoB 프로세스를 감지해 Agent를 시작하거나 기존 Agent에 PID 전달 |
| Electron 메인 프로세스 | 단일 실행, 창 수명주기, 연결할 PoB 프로세스 선택·종료 감지, MCP 프로세스 및 모델 연결 관리 |
| React 렌더러 | 채팅, 준비·오류 상태, 복수 PoB 프로세스 선택, 현재 빌드명과 감시자 시작 설정 표시 |
| preload/IPC 브리지 | 렌더러에 명시적으로 필요한 최소 API만 제공 |
| Python MCP 서버 | Agent와 분리된 프로세스로 실행하며 stdio로 통신. 개발·배포 실행 방식은 [Agent 패키징 및 배포](agent-packaging.md), 도구와 계산 경계는 [MCP 문서](../MCP.md) 참조 |

렌더러에 Node/Electron 전체 권한을 노출하지 않습니다. PoB 연결 및 MCP 프로세스 제어는 메인 프로세스가 소유합니다. PoB bridge와 모델 연결의 통신·인증 세부는 [PoB bridge 문서](pob-bridge.md)에서 정의합니다.

### 창과 연결 프로세스 수명주기

- 감시자는 PoB 프로세스를 감지하면 Agent를 실행하고 PID를 전달합니다. Agent가 이미 실행 중이지만 연결 대상이 없을 때는 기존 프로세스에 첫 연결 후보를 전달합니다. 연결이 성립한 뒤에는 추가 PoB 프로세스를 무시합니다.
- 연결 후보가 하나면 자동 연결합니다. 여러 개면 사용자가 Agent에서 연결할 PoB 프로세스를 고릅니다. 이 선택은 빌드 파일을 고르는 동작이 아닙니다.
- 연결 후 새 PoB가 시작되어도 현재 연결을 바꾸지 않습니다. 연결된 PoB가 종료되면 Agent를 종료하며, 다른 실행 중 PoB로 자동 승계하지 않습니다.
- 감시자는 Windows 로그인 자동 실행이 기본이며 설정에서 수동 실행으로 바꿀 수 있습니다.

### 채팅 상태와 준비 절차

- 초기 상태는 준비 중이며 채팅 입력은 비활성화합니다. MCP 서버와 모델 연결이 모두 준비됐을 때만 입력을 활성화합니다.
- 각 준비 시도는 최대 10초이며, 실패 후 0.5초 뒤 재시도합니다. 첫 시도를 포함해 3회 실패하면 채팅 영역에 오류와 재시도 동작을 노출합니다. 사용자에게는 재시도 횟수별 중간 오류를 보이지 않습니다.
- 채팅 메시지, 스트리밍 응답, 요청 상태 및 FIFO 대기열은 앱 메모리에만 유지합니다.
- 응답 생성 중 제출한 프롬프트를 대기열에 넣고, 현재 요청 완료 시 하나씩 보냅니다. 실패하면 큐를 멈추고 실패 항목을 편집 가능한 입력으로 복사합니다. 사용자의 재전송은 큐 앞에서 처리합니다.
- 요청은 전송 순간의 연결된 PoB의 활성 빌드 경로에 묶입니다. 경로 변경은 진행 중 요청의 입력을 바꾸지 않고, 다음 전송부터 새 경로를 사용합니다. 사용자가 다른 빌드명을 명시한 요청은 해당 요청만 그 빌드 경로를 사용합니다.

## 4. 완료 기준

- PoB 실행으로 Agent가 자동 시작되고 창이 표시되며, Agent 중복 실행 없이 기존 인스턴스에 연결 이벤트가 전달됩니다.
- 연결 후보가 하나면 자동 연결하고, 여러 개면 사용자가 PoB 프로세스를 선택합니다. 빌드 파일 선택 UI는 제공하지 않습니다.
- 감시자의 로그인 자동 실행/수동 실행 설정이 동작하며 기본값은 로그인 자동 실행입니다.
- 연결된 PoB의 현재 빌드명을 표시하고, 연결된 PoB의 빌드 경로가 바뀌면 이후 요청부터 새 경로를 사용합니다.
- 다른 빌드명을 지정한 요청은 저장 폴더 검색 결과 하나일 때 바로 분석하고, 여러 후보면 확인을 요청하며, 후보가 없으면 이름을 구체화하도록 안내합니다.
- Agent 창 닫기와 선택된 PoB 종료가 앱 종료로 이어지고, 재실행 시 대화와 대기열은 복원되지 않습니다.
- 준비 전 입력이 차단되고, 각 10초 제한과 0.5초 간격으로 총 세 번 준비 시도한 후 재시도가 제공됩니다.
- 스트리밍, FIFO 큐, 개별 큐 삭제, 실패 정지·편집·재전송 및 다음 요청 자동 진행이 확인됩니다.
- 같은 PoB의 활성 빌드 경로가 바뀌어도 현재 요청은 기존 경로를 사용하고 다음 요청부터 새 경로를 사용합니다. 다른 빌드 분석은 기본 PoB 맥락을 바꾸지 않습니다.
- Electron 메인 프로세스가 모델 연결과 Python MCP 프로세스를 관리하고, 렌더러에는 좁은 preload/IPC API만 노출됩니다.
