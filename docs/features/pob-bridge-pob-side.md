# PoB 측 브리지 변경 사항

> 상태: 송신 코드를 `.pob/Path of Building Community` 개발용 복사본에 구현했다. Agent에서 선택한 설치 폴더에 자동 적용하는 기능은 별도 작업이다.

이 문서는 PoB Agent가 현재 활성화된 저장 빌드를 따라갈 수 있도록 개발용 복사본과 사용자가 선택한 설치본에 적용할 최소 PoB 변경 방법을 정의한다. 연결 버튼과 재시작 안내 같은 사용자 흐름은 [PoB 브리지](pob-bridge.md)에 정의되어 있다. 에이전트 창과 프로세스 선택 동작은 [에이전트 창](agent-window.md)에 정의되어 있다.

## 합의된 PoB 측 범위

PoB 소스는 활성 빌드의 저장 파일 경로를 상태 파일로 알리는 데 필요한 부분만 수정한다. PoB는 에이전트를 실행하거나 종료를 알리지 않는다. 별도의 감시자 프로세스가 PoB를 감지하고 Agent를 실행하는 일은 별도 작업이다. Agent는 상태 파일의 PID를 기준으로 프로세스 실행 상태를 감시한다.

PoB 연동은 활성 저장 빌드 파일의 경로만 보낸다. 파일 경로의 상위 폴더를 빌드 검색 경로로 사용하므로 별도의 폴더 필드는 전송하지 않는다. PoB는 빌드 내용, 계산 결과, 메모리 상태 또는 저장되지 않은 수정 사항을 보내지 않는다.

경로 알림은 다른 저장 빌드를 선택하는 경우를 다룬다. 에이전트의 기본 대화 맥락은 선택한 PoB의 현재 저장 빌드를 따른다. 사용자가 다른 저장 빌드를 명시하면 에이전트는 해당 요청에 한해 그 빌드를 찾는다. 이 동작은 PoB의 활성 빌드나 에이전트의 기본 맥락을 변경하지 않는다.

## 연결 및 빌드 동작

- 감시자는 PoB 프로세스가 실행되는 것을 감지해 Agent를 시작하고 PID를 전달한다. Agent가 이미 실행 중이고 연결 대상이 없으면 Electron 단일 인스턴스 이벤트로 후보 PID를 전달한다.
- 감시자는 Windows 로그인 시 자동으로 시작하거나 수동으로 시작할 수 있다. 기본값은 로그인 시 자동 실행이다.
- 브리지가 설치된 PoB가 하나 실행 중이면 Agent가 자동 연결하고, 여러 개면 사용자가 연결 대상을 선택한다. 감시자가 전달한 PID가 있어도 여러 후보면 자동 연결하지 않는다. 최초 연결 후에는 연결 대상을 변경할 수 없다.
- Agent 연결 버튼을 누르면 사용자가 PoB 설치 폴더를 선택하고 Agent가 해당 PoB 파일을 자동 수정해 브리지를 설치한다. PoB는 실행 중인 코드를 다시 읽지 않으므로 재시작이 필요하며 Agent가 강제로 종료하지 않는다.
- 사용자가 Agent를 종료하면 PoB가 모두 종료될 때까지 감시자는 Agent를 자동 실행하지 않는다. 수동 실행은 허용한다.
- 선택된 PoB 프로세스가 종료되면 에이전트도 종료된다. 현재 버전은 실행 중인 다른 PoB로 연결을 넘기지 않는다. 사용자는 에이전트를 다시 열어 다른 프로세스를 선택할 수 있다.
- 선택된 프로세스가 보낸 PoB 빌드 경로 알림은 에이전트의 기본 빌드 맥락을 갱신한다. 다른 PoB 프로세스가 보낸 알림은 반영하지 않는다.
- PoB는 `%APPDATA%/pob-agent/pob-bridge/<PID>.json` 상태 파일을 기록한다. 이는 현재 앱의 `app.getPath('userData')/pob-bridge`와 같은 위치다. 파일에는 `{"pid": 1234, "buildPath": "C:\\...\\build.xml"}`만 담고, 저장된 빌드가 없으면 `buildPath`를 `null`로 기록한다. Agent는 유효한 경로의 상위 폴더를 빌드 검색 경로로 사용한다.
- LuaJIT FFI의 `GetCurrentProcessId`로 PoB PID를 얻고, `dkjson`으로 상태 JSON을 만든다. 먼저 `<PID>.json.tmp`에 쓴 뒤 `MoveFileExA`의 replace-existing 및 write-through 옵션으로 본 파일을 교체한다.
- `Modules/Main.lua`는 `PobAgentBridgeDraft`를 로드하고, 프레임에서 모드 변경이 끝난 뒤 BUILD 모드의 `GetArgs()` 첫 반환값(저장 빌드 경로)을 전달한다. 송신 함수는 경로가 이전과 같으면 파일을 다시 쓰지 않으므로 빌드 내부 값 수정은 상태 파일 갱신을 만들지 않는다. 저장 경로가 없으면 `null`을 기록한다.
- PoB 시작 시 현재 선택된 빌드를 한 번 알리고, 이후에는 사용자가 다른 빌드를 선택할 때만 상태 파일을 갱신한다. 같은 빌드 안의 값 변경은 파일에 반영하지 않는다.
- 저장된 빌드가 없을 때의 대화 응답과 다른 빌드 검색 규칙은 [에이전트 창](agent-window.md)에서 정의한다.

## 구성 요소별 책임

| 구성 요소 | 책임 |
| --- | --- |
| PoB 프로세스 감시자 | 저장된 시작 설정에 따라 실행되고, PoB 프로세스를 감지하며, Agent를 시작하거나 실행 중인 Agent에 후보 PID를 전달한다 |
| 에이전트 앱 | 연결 상태를 확인하고 필요하면 사용자가 지정한 PoB 폴더에 브리지를 적용하며 연결 후보·종료·빌드 경로를 관리한다 |
| PoB 측 브리지 코드 | PoB의 활성 저장 빌드가 바뀔 때 해당 빌드 파일 경로를 에이전트에 알린다 |
| 로컬 빌드 리더 및 분석 도구 | 저장된 빌드 파일을 로컬에서 읽고 요청된 빌드에 대한 도구 결과를 제공한다 |

## PoB 소스 조사 및 구현 범위

PoB 측 변경은 사용자의 설치본과 분리해 둔 개발용 복사본에서 구현한다. 개발 중 설치본을 수정하지 않는다. 개발용 복사본을 변경하기 전에 현재 버전을 확인하고 대상 원본 파일을 보존하며, 업데이트가 실험 내용을 예고 없이 덮어쓰지 않도록 업데이트 방식을 조사한다.

PoB 개발 복사본에서 활성 저장 빌드 전환과 초기 미저장 상태의 전송은 구현했다. 저장, 다른 이름으로 저장, 빌드 닫기, 비ASCII 사용자 경로, FFI 실패 및 실제 Agent 수신까지의 통합 검증은 남아 있다. 빌드 내용이 바뀌었지만 저장 경로가 같은 경우 상태 파일은 갱신하지 않는다.

PoB 송신기는 `%APPDATA%/pob-agent/pob-bridge`를 고정 공유 경로로 사용한다. TCP, 포트, 토큰은 사용하지 않는다. Agent와 PoB가 이 고정 경로를 공유하므로 설치 위치나 패키징 형태에 따라 상태 파일 경로를 바꾸지 않는다.

## 설치본에 적용할 변경

- 사용자가 Agent의 연결 버튼에서 선택한 경로를 대상 PoB 설치 폴더로 사용한다.
- Agent는 이 문서의 상태 파일 송신 구현과 동일한 최소 변경을 설치본에 적용한다. 변경 범위는 `PobAgentBridgeDraft` 송신 모듈 추가와 `Modules/Main.lua`에서의 로드·호출 연결이다.
- PoB 측 코드는 현재 프로세스 PID와 활성 저장 빌드의 `buildPath`를 상태 파일로 기록한다. 저장 빌드가 없으면 `buildPath`는 `null`이다. 설치본 적용을 위해 별도 통신 방식이나 빌드 데이터 전달을 추가하지 않는다.
- Agent는 파일 적용 뒤 사용자에게 PoB 재시작이 필요하다고 안내한다. 실행 중인 PoB를 강제로 종료하지 않는다.
- Agent는 위 변경 외의 PoB 파일이나 동작을 수정하지 않는다. UI 사용자 흐름은 [PoB 브리지](pob-bridge.md)를 따른다.

## 완료 기준

- PoB 소스 변경은 활성 저장 빌드 경로를 알리는 데 필요한 부분으로 한정된다.
- 다른 저장 빌드를 선택하면 이후 요청에 적용될 에이전트의 기본 경로가 갱신된다.
- PoB에서 빌드 XML, 빌드 내용, 계산 결과, 메모리 상태 또는 저장되지 않은 수정 사항을 보내지 않는다.
- 저장 경로가 없는 빌드를 이전 저장 빌드로 표시하지 않는다.
- 에이전트가 전달된 경로의 파일을 로컬에서 읽으며, 파일이 없거나 읽을 수 없는 경우 사용할 수 없는 빌드로 표시한다.
- 선택되지 않은 PoB에서 발생한 경로 이벤트가 선택된 PoB의 빌드 맥락을 바꾸지 않는다.
- 다른 빌드명을 검색해도 PoB의 활성 경로나 이후 생략된 빌드 참조에 적용되는 기본 맥락이 바뀌지 않는다.

## 별도 작업

- Agent 연결 버튼에서 사용자가 선택한 PoB 설치 폴더에 브리지를 자동 적용한다.
- 적용 후 Agent에 PoB 재시작 필요 상태를 표시하고, 재실행 후 상태 파일 연결을 검증한다.
- 저장 빌드 선택, 미저장 상태, 빌드 전환, PoB 종료 및 상태 파일 정리를 개발 복사본에서 검증한다.
- 패키징된 Agent와 설치된 PoB 조합, 비ASCII 경로 및 파일 이벤트 처리를 검증한다.

## 미결정 사항

- 설치본에서 수정할 파일의 정확한 상대 경로와 `Modules/Main.lua`에 연결 코드를 넣을 기준 위치, 지원할 PoB 버전 판별 기준
- 기존 파일 백업·복구·제거, 이미 수정된 설치본 처리 및 업데이트 후 재적용 규칙
- 쓰기 권한이 없는 설치 폴더와 지원하지 않는 폴더에 대한 안내
- 연결 버튼의 설치 상태 검사와 설치 실패 처리 세부
