# PoB 측 브리지 변경 사항

> 상태: 제품 동작은 합의됨. PoB 구현 세부 사항은 미결정. 이 기능을 위해 PoB 소스는 아직 수정하지 않았다.

이 문서는 PoB Agent가 현재 활성화된 저장 빌드를 따라갈 수 있도록 사용자가 설치본과 분리해 둔 Path of Building(PoB) Community 개발용 복사본에 필요한 최소 변경 사항을 정의한다. 사용자에게 보이는 연결 동작은 [PoB 브리지](pob-bridge.md)에 정의되어 있다. 에이전트 창과 프로세스 선택 동작은 [에이전트 창](agent-window.md)에 정의되어 있다.

## 합의된 PoB 측 범위

PoB 소스는 활성 빌드의 저장 파일 경로가 바뀔 때 에이전트에 알리는 데 필요한 부분만 수정한다. PoB는 에이전트를 실행하거나 PID를 보내거나, PoB가 종료되었음을 에이전트에 알리지 않는다. 별도의 감시자 프로세스가 PoB 프로세스를 감지하고 에이전트를 실행한 뒤 프로세스 식별자를 전달한다. 에이전트는 선택된 프로세스의 실행 상태를 감시한다.

PoB 연동은 활성 저장 빌드 파일의 경로만 보낸다. 에이전트는 해당 파일을 로컬에서 읽고 경로에서 화면에 표시할 빌드명을 가져온다. PoB는 빌드 내용, 계산 결과, 메모리 상태 또는 저장되지 않은 수정 사항을 보내지 않는다.

경로 알림은 다른 저장 빌드를 선택하는 경우를 다룬다. 에이전트의 기본 대화 맥락은 선택한 PoB의 현재 저장 빌드를 따른다. 사용자가 다른 저장 빌드를 명시하면 에이전트는 해당 요청에 한해 그 빌드를 찾는다. 이 동작은 PoB의 활성 빌드나 에이전트의 기본 맥락을 변경하지 않는다.

## 연결 및 빌드 동작

- 감시자는 PoB 프로세스가 실행되는 것을 감지해 에이전트를 시작한다. 선택된 PoB가 없는 에이전트가 이미 실행 중이면 중복 실행하지 않고 해당 인스턴스에 PID를 전달한다. 에이전트가 PoB 하나를 선택한 뒤에는 나중에 실행된 PoB를 무시한다.
- 감시자는 Windows 로그인 시 자동으로 시작하거나 수동으로 시작할 수 있다. 기본값은 로그인 시 자동 실행이다.
- 에이전트가 처음 연결할 때 사용 가능한 PoB 프로세스가 하나면 해당 프로세스에 연결한다. 여러 개면 사용자가 에이전트에서 프로세스를 선택한다. 연결한 뒤에는 이후 실행되는 PoB가 선택된 프로세스를 대체하지 않는다.
- 선택된 PoB 프로세스가 종료되면 에이전트도 종료된다. 현재 버전은 실행 중인 다른 PoB로 연결을 넘기지 않는다. 사용자는 에이전트를 다시 열어 다른 프로세스를 선택할 수 있다.
- 선택된 프로세스가 보낸 PoB 빌드 경로 알림은 에이전트의 기본 빌드 맥락을 갱신한다. 다른 PoB 프로세스가 보낸 알림은 반영하지 않는다.
- PoB는 Agent의 `app.getPath('userData')/pob-bridge` 공유 디렉터리에 `<PID>.json` 상태 파일을 기록한다. 파일에는 `{"pid": 1234, "buildPath": "C:\\...\\build.xml"}`만 담고, 저장된 빌드가 없으면 `buildPath`를 `null`로 기록한다. 세부 파일 위치와 수신 동작은 [PoB 브리지](pob-bridge.md)를 따른다.
- PoB 시작 시 현재 선택된 빌드를 한 번 알리고, 이후에는 사용자가 다른 빌드를 선택할 때만 상태 파일을 갱신한다. 같은 빌드 안의 값 변경은 파일에 반영하지 않는다.
- 분석할 수 있는 대상은 저장된 빌드 파일뿐이다. 선택한 빌드에 저장 파일 경로가 없거나 전달된 파일을 찾을 수 없거나 읽을 수 없으면 에이전트는 해당 빌드를 분석할 수 없다고 알린다. 이전 빌드를 현재 빌드인 것처럼 조용히 사용하지 않는다.
- 대화에서 “이 빌드”, “우리 빌드”와 같은 표현은 선택된 PoB의 현재 저장 빌드를 뜻한다. 사용자가 다른 빌드명을 말하면 에이전트는 설정된 빌드 폴더에서 검색한다. 결과가 하나면 바로 분석하고, 여러 개면 사용자 확인을 받는다. 결과가 없으면 찾지 못했다고 알리고 빌드명을 확인해 달라고 요청한다.

## 구성 요소별 책임

| 구성 요소 | 책임 |
| --- | --- |
| PoB 프로세스 감시자 | 저장된 시작 설정에 따라 실행되고, PoB 프로세스를 감지하며, 에이전트를 시작하고, 에이전트에 선택된 PoB가 없을 때 최초 후보 PID를 전달한다 |
| 에이전트 앱 | 후보가 여러 개일 때 PoB 프로세스를 선택하고, 선택한 PID를 보관하며, 프로세스 종료를 감시하고, 기본 빌드 맥락을 관리하며, 개별 요청에 필요한 다른 빌드를 찾는다 |
| PoB 측 브리지 코드 | PoB의 활성 저장 빌드가 바뀔 때 해당 빌드 파일 경로를 에이전트에 알린다 |
| 로컬 빌드 리더 및 분석 도구 | 저장된 빌드 파일을 로컬에서 읽고 요청된 빌드에 대한 도구 결과를 제공한다 |

## PoB 소스 조사 및 구현 범위

PoB 측 변경은 사용자의 설치본과 분리해 둔 개발용 복사본에서 구현한다. 개발 중 설치본을 수정하지 않는다. 개발용 복사본을 변경하기 전에 현재 버전을 확인하고 대상 원본 파일을 보존하며, 업데이트가 실험 내용을 예고 없이 덮어쓰지 않도록 업데이트 방식을 조사한다.

활성 저장 빌드 변경을 감지할 정확한 훅은 정해지지 않았다. 현재 PoB 소스를 조사해 관련 모드 또는 빌드 전환 뒤 훅이 선택된 파일의 안정적인 경로를 전달하는지 검증한다. 저장 빌드 선택, 저장, 다른 이름으로 저장, 빌드 제거 또는 닫기, 활성 저장 파일이 없는 상태로의 전환을 확인한다. 임시 파일이나 저장되지 않은 빌드를 가리키는 경로는 보내지 않는다.

PoB 측 모듈, 훅 위치, 프로세스와 경로의 연결 방식, 로컬 IPC 프로토콜, 재시도 동작 및 메시지 인증 방식은 미결정이다. 경로를 알리는 데 필요한 최소한의 PoB 변경을 선택하고, 구현 전에 필요한 에이전트 측 대응 사항을 문서화한다.

## 완료 기준

- PoB 소스 변경은 활성 저장 빌드 경로를 알리는 데 필요한 부분으로 한정된다.
- 다른 저장 빌드를 선택하면 이후 요청에 적용될 에이전트의 기본 경로가 갱신된다.
- PoB에서 빌드 XML, 빌드 내용, 계산 결과, 메모리 상태 또는 저장되지 않은 수정 사항을 보내지 않는다.
- 저장 경로가 없는 빌드를 이전 저장 빌드로 표시하지 않는다.
- 에이전트가 전달된 경로의 파일을 로컬에서 읽으며, 파일이 없거나 읽을 수 없는 경우 사용할 수 없는 빌드로 표시한다.
- 선택되지 않은 PoB에서 발생한 경로 이벤트가 선택된 PoB의 빌드 맥락을 바꾸지 않는다.
- 다른 빌드명을 검색해도 PoB의 활성 경로나 이후 생략된 빌드 참조에 적용되는 기본 맥락이 바뀌지 않는다.

## 미결정 구현 사항

- 활성 저장 빌드 경로 변경을 감지할 정확한 PoB 소스 모듈과 수명 주기 훅
- PID 전달은 감시자가 담당하면서 PoB 경로 알림을 선택된 PID와 연결하는 방법
- PoB에서 공유 디렉터리 경로를 구하고 상태 파일을 기록할 훅 위치
- 상태 파일을 갱신할 때 Agent가 부분적으로 기록된 JSON을 읽지 않도록 하는 방법
- 에이전트가 설정된 빌드 폴더의 위치를 얻고 그 안에서 이름을 검색하는 방법
- PoB 버전 호환성, 연결 코드의 설치·백업·업데이트·제거·복구 방법
- Windows 로그인 시 감시자를 설치하거나 등록하는 방법과 수동 시작 설정의 적용 방법
- 선택된 PoB가 계속 실행 중일 때 사용자가 에이전트를 닫으면 어떻게 동작할지

PoB 연동을 완료한 것으로 보기 전에 이러한 구현 사항을 개발용 복사본과 에이전트에서 검증해야 한다.
